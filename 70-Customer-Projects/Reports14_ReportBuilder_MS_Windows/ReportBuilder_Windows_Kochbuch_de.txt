================================================================================
  Oracle Reports Builder 14.1.2 unter Windows Server einrichten
  (minimale Entwicklungsumgebung - Builder-Domain OHNE Reports-Server)
================================================================================
  Zielgruppe : Windows-/Oracle-Administrator beim Kunden
  Umgebung   : Windows Server 2022 (zertifiziert; 2025 nur getestet),
               FMW 14.1.2.0.0, Oracle Reports 14.1.2, Patchstand CPU Okt 2026
  Erstellt   : 2026-10-26
  Grundlage  : Oracle-Doku Forms 14.1.2 Kap. 5 + Reports-Installation 12.2.1.3
               (gilt laut Oracle unveraendert fuer 14.1.2), pipperr.de
               "Oracle Reports 14c unter Windows", IHateWeblogic 70-Customer-
               Projects/Reports14_Only_manuall_install (Linux-Server, gleicher
               Kunde). Hintergrund und Entscheidung: README.md in diesem Ordner.
  Status     : DOKUMENTIERT - beim Kunden live zu pruefen. Jeder Schritt ist
               markiert: [Doku] = aus der Oracle-Doku / dem Linux-Server
               uebernommen, [live] = auf einem Windows-System bestaetigt.

  Ziel       : Entwickler starten per RDP den Reports Builder
               (rwbuilder.bat). Es laeuft KEIN WebLogic, kein Windows-Dienst,
               kein SSL. Die Berichte laufen zum Testen auf dem
               Linux-Reports-Server.
  Warum eine Domain trotzdem: Der Builder braucht eine Reports-Tools-
               Instanz ("One ReportsTools component is compulsory"); das
               Template "Oracle Reports Tools" verlangt Oracle JRF + EM ->
               RCU-Schemas in einer Datenbank sind Pflicht. Einen
               "Standalone Reports Builder" wie bei Forms gibt es nicht.
================================================================================

VORAUSSETZUNGEN  (Werte EINMAL an die Umgebung anpassen)
---------------------------------------------------------
  Alle Befehle in einer "cmd"-Shell mit "Als Administrator ausfuehren"
  (Oracle: sonst schlaegt die Konfiguration still fehl). Installiert wird mit
  EINEM lokalen Administrator-Konto (z.B. ORASYSTEM) - immer mit demselben.

    set ORACLE_BASE=E:\oracle
    set ORACLE_HOME=E:\oracle\fmw
    set JDK_HOME=E:\Java\jdk-21
    set JAVA_HOME=%JDK_HOME%
    set PATCH_STORAGE=E:\oracle\patch_storage
    set DOMAIN_HOME=E:\oracle\user_projects\domains\rwbuilder_domain
    set STAGE=E:\oracle\stage
    rem RCU-Datenbank (bestehende DB des Kunden) und eigenes Praefix:
    set DB_HOST=<db-host>
    set DB_PORT=1521
    set DB_SERVICE=<pdb-service>
    set DB_SCHEMA_PREFIX=RWDEV

  Regeln:
  - Pfade OHNE Leerzeichen und kurz halten (Windows: lange
    Umgebungsvariablen brechen Reports - Oracle Install 12.2.1.3 Anhang B.3).
  - Rechnername und IP nach der Installation NICHT mehr aendern.
  - Englisches Windows bevorzugen (Fehlermeldungen fuer Oracle Support).
  - Virenschutz: Ausnahme fuer E:\oracle waehrend Installation und Patchen
    (Patch-READMEs: "anti-virus software should be temporarily stopped").

  Benoetigte Software (in %PATCH_STORAGE%):
    V1045135-01.zip  FMW Infrastructure 14.1.2.0.0 (Linux UND Windows, generic)
                     SHA-256 1AAE35167BDED101E7194AA3D75C26B292010035A36C289A3F90B663D84E68BD
    V1045122-01.zip  Forms and Reports 14.1.2.0.0 for Microsoft Windows x64
                     SHA-256 26478C4DC2EDB4A897226F07D7AEC6F675754853F00495D4BAF2AAC1D9B8D2CE
    p35702194_2100_MSWIN-x86-64.zip  Oracle JDK 21 (MOS, Plattform Windows x64)
    Patches CPU Oktober 2026 (MOS, Schritt 4) - plattformabhaengige ZIPs in
    der Variante "Microsoft Windows x64 (64-bit)" (getMOSPatch: 233P)
    Microsoft Visual C++ Redistributable x64 UND x86 (sonst meldet der
    Builder "MSVCP100.dll nicht gefunden"):
      https://aka.ms/vs/17/release/vc_redist.x64.exe
      https://aka.ms/vs/17/release/vc_redist.x86.exe

SCHRITT 1: Windows vorbereiten und JDK installieren  [Doku]
================================================================================

  rem 1.1 Visual C++ Runtime (x64 und x86) installieren, dann:
  mkdir E:\temp E:\oracle E:\Java %PATCH_STORAGE% %STAGE%

  rem 1.2 JDK aus MOS-Patch 35702194 - die Version steht NUR im ZIP
  rem     (Stand CPU Okt 2026: jdk-21.0.13.0.2; der Alert-Build, die
  rem     21.0.13 des CPU selbst ist betroffen)
  cd %PATCH_STORAGE%
  tar -tf p35702194_2100_MSWIN-x86-64.zip | findstr /i "jdk-21"
  tar -xf p35702194_2100_MSWIN-x86-64.zip -C %STAGE%
  tar -xf %STAGE%\jdk-21.0.13.0.2_windows-x64_bin.zip -C E:\Java

  rem 1.3 Versionsneutraler Pfad als Verzeichnis-Verbindung (Junction) -
  rem     ein spaeteres JDK-Update ist dann nur: neues JDK daneben,
  rem     Builder schliessen, Junction neu setzen
  mklink /J E:\Java\jdk-21 E:\Java\jdk-21.0.13.0.2
  E:\Java\jdk-21\bin\java -version

  rem 1.4 JAVA_HOME systemweit (neue cmd-Shell danach oeffnen)
  setx /M JAVA_HOME E:\Java\jdk-21

  rem 1.5 SecureRandom-Fix (schnellerer WebLogic-Start; unter Windows
  rem     unkritisch, aber wie auf dem Linux-Server einheitlich)
  rem     E:\Java\jdk-21\conf\security\java.security:
  rem       securerandom.source=file:/dev/./urandom

  rem 1.6 Datenbank erreichbar? (vom Windows Server aus)
  powershell -Command "Test-NetConnection %DB_HOST% -Port %DB_PORT%"

SCHRITT 5: RCU-Schemas in der bestehenden Datenbank anlegen  [Doku]

  %ORACLE_HOME%\oracle_common\bin\rcu.bat

  rem   Database Type     : Oracle Database enabled for edition-based

  rem   User sys, Role SYSDBA (oder ein DBA mit den RCU-Rechten)
  rem   Create new Prefix : RWDEV
  rem   Komponenten       : STB, MDS, OPSS, IAU, IAU_APPEND, IAU_VIEWER,
  rem                       UCSUMS, WLS

SCHRITT 10: Betrieb, Patchen, bekannte Probleme
================================================================================

  Patchen: bei jedem Patchzyklus dieselben Nummern wie auf dem
  Linux-Server, in der Windows-Variante (Schritt 4). Vorher alle
  Builder-Sitzungen beenden. JDK-Update: neues JDK nach E:\Java,
  Junction E:\Java\jdk-21 umsetzen (Schritt 1.3).

  Der AdminServer muss im Alltag NICHT laufen. Er wird nur gebraucht, um
  eine weitere Tools-Instanz anzulegen oder die Domain zu aendern.

  Problem: "MSVCP100.dll wurde nicht gefunden" beim Start des Builders
  Loesung: Visual C++ Redistributable x64 UND x86 installieren (Schritt 1)

  Problem: Builder startet nicht, Fehler zu OPSS / Datenbank
  Ursache: Kennwort eines RWDEV_*-Schemas abgelaufen oder Konto gesperrt
  Loesung: DB-Team: Profil RCU_USER, Konto entsperren (Schritt 5)

  Problem: Vorschau im Builder sieht anders aus als die PDF vom Server
  Ursache: andere Fonts / uifont.ali als auf dem Linux-Server
  Loesung: Schritt 8.3, Font_kochbuch_de.txt

  Problem: Reports-Fehler wegen zu langer Pfade / Umgebungsvariablen
  Ursache: Windows-Grenze fuer Umgebungsvariablen (Oracle Install 12.2.1.3
           Anhang B.3)
  Loesung: kurze Pfade ohne Leerzeichen, PATH nicht unnoetig verlaengern

  Problem: Bericht laeuft im Builder, auf dem Server nicht
  Ursache: unterschiedlicher Patchstand Builder / Server, andere
           Verbindungs-Aliase, Bilder/Bibliotheken nicht im REPORTS_PATH des
           Servers
  Loesung: lspatches beider Seiten vergleichen; tnsnames und Pfade abgleichen
