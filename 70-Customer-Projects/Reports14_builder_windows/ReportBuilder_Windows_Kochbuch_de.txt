  Alle Befehle in einer "cmd"-Shell mit "Als Administrator ausfuehren"

  BENUTZERKONTEN DER ENTWICKLER  [live 2026-10-27]
  ------------------------------------------------
  Mit einem normalen Benutzerkonto (ohne Admin-Rechte) laesst sich der
  Builder nach der Installation NICHT starten:
  - Der Oracle-Installer bricht beim Installieren die Rechte-Vererbung
    unter E:\oracle (setzt eigene, explizite Rechte auf die Unterordner).
  - Eine Gruppe, die man auf E:\oracle berechtigt (z.B. "Reports-
    Entwickler", Lesen/Ausfuehren), kommt deshalb in den Unterordnern
    nicht an.
  - Die Rechte muessten Ordner fuer Ordner von Hand gesetzt werden - sehr
    aufwendig, fehleranfaellig und nach Patches erneut zu pruefen
    (Annahme: OPatch legt Dateien mit den Rechten des Installationskontos
    an).
  Entscheidung: Die Entwickler arbeiten per RDP mit einem Konto mit
  LOKALEN ADMINISTRATOR-RECHTEN auf diesem Server.
  - Je Entwickler ein EIGENES Konto (persoenlich, nicht ORASYSTEM teilen),
    Mitglied der lokalen Gruppe "Administratoren".
  - Der Server dient nur der Builder-Entwicklung (keine Produktion, keine
    weiteren Dienste); Zugriff nur per RDP aus dem Admin-/Entwicklernetz.
  - Lizenz-Nebeneffekt: Windows Server erlaubt 2 gleichzeitige
    Admin-RDP-Sitzungen OHNE RDS-Lizenzen - passt fuer 2 Entwickler; ab dem
    dritten gleichzeitigen Benutzer RDS-Lizenzierung beim Kunden klaeren.

  Regeln:
  - Pfade OHNE Leerzeichen und kurz halten (Windows: lange
    Umgebungsvariablen brechen Reports - Oracle Install 12.2.1.3 Anhang B.3).
  - Rechnername und IP nach der Installation NICHT mehr aendern.
  - Englisches Windows bevorzugen (Fehlermeldungen fuer Oracle Support).
  - Virenschutz: Ausnahme fuer E:\oracle waehrend Installation und Patchen
    (Patch-READMEs: "anti-virus software should be temporarily stopped").

  Loesung: DB-Dienst starten; DB-Team: Profil RCU_USER, Konto entsperren
