# Security weighting of the findings of analyse_forms_reports_export.sh
# (traffic light "Status at a glance" of the Forms & Reports status report).
#
# Format: <extended regexp on "area;finding">;<category>;<weight>
#   - first matching line wins (put specific rules first)
#   - matched case-insensitively against "<area>;<finding text>" of a
#     WARN / HINT / INFO finding (findings.csv)
#   - category: one of the names below (same spelling = same row in the table)
#   - weight:
#       critical  exploitable from the network today without a login -> category RED
#       high      weakens the protection substantially / needs one more step -> YELLOW
#       low       hardening / good practice -> category stays green (counted)
#       none      not a security point (only listed, not counted)
# A security finding ("Security / ...") without a matching line is reported as
# "unrated" by the analysis run - add a line here.
# Overall light = the worst category.
