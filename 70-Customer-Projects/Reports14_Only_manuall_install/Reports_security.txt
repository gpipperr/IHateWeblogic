VORAUSSETZUNGEN
----------------
  - Installation nach Reports_kochbuch_de.txt ist abgeschlossen, Reports
    laufen (Funktionstest Schritt 9.11 erfolgreich).
  - SSL ist eingerichtet: Nginx terminiert TLS (SSL_Kochbuch_de.txt,
    FMW_Kochbuch_de.txt). WebLogic selbst laeuft NUR auf localhost.
  - Diese Anleitung aendert Sicherheitseinstellungen. Vor JEDEM Schritt die
    genannte Datei sichern. Nach jedem Schritt den Funktionstest
    (ABSCHLUSS-CHECKLISTE) machen - nicht alles auf einmal umstellen, sonst
    ist bei einem Fehler nicht erkennbar, welche Aenderung ihn ausgeloest
    hat.
  - Benutzer, Rollen und Richtlinien werden je ZWEIMAL beschrieben:
      Weg A: ueber die Oberflaeche (Enterprise Manager, /em)
      Weg B: als WLST-Befehle zum Selbst-Eintippen (interaktive WLST-Sitzung)
    Beide Wege fuehren zum selben Ergebnis - nur EINEN davon ausfuehren.
  - Hinweis zu den Oberflaechen: WebLogic 14.1.2 hat KEINE klassische
    Administration Console (/console) mehr. Die Oberflaeche fuer Benutzer
    und Rollen ist der Enterprise Manager (Fusion Middleware Control),
    der mit "Oracle JRF" in der Domain liegt und auf dem AdminServer
    laeuft: http://localhost:7001/em
  - Menuetexte: Englisch (Deutsch) - deutsche Begriffe erscheinen nur bei
    deutscher Browser-/Konsolensprache.

  Variablen fuer diese Anleitung (Werte an die Umgebung anpassen - die
  Beispielwerte entsprechen Reports_kochbuch_de.txt):

SCHRITT 1: Netzwerk - WebLogic nur lokal erreichbar  (als root / oracle)
================================================================================

  # Ziel: von aussen ist NUR Nginx (443, 80 -> Umleitung auf 443)
  # erreichbar. AdminServer (7001), Reports-Managed-Server (9002) und Node
  # Manager (5556) hoeren nur auf localhost.

  # 1.1 Listen-Adressen in der Domain pruefen (als oracle)
  grep -n "<listen-address>" $DOMAIN_HOME/config/config.xml
  grep -E "^ListenAddress" $DOMAIN_HOME/nodemanager/nodemanager.properties
  # Erwartet: localhost oder 127.0.0.1 (leere listen-address = ALLE
  # Adressen -> dann im EM unter Server -> Einstellungen auf localhost
  # setzen und den Server neu starten).

  # 1.2 Firewall: nur 80/443 + Reports-UDP-Port (als root)
  firewall-cmd --permanent --remove-port=7001/tcp 2>/dev/null
  firewall-cmd --permanent --remove-port=9002/tcp 2>/dev/null
  firewall-cmd --permanent --remove-port=5556/tcp 2>/dev/null
  firewall-cmd --reload
  firewall-cmd --list-ports
  # Der Reports-Broadcast-Port (UDP, z.B. 14027) BLEIBT offen - der
  # Reports-Server braucht ihn zum Start (sonst REP-50600).

  # 1.3 Zugriff auf AdminServer/EM fuer Administratoren: am sichersten
  #     ueber einen SSH-Tunnel statt ueber Nginx (vom Admin-PC aus):
  #       ssh -L 7001:127.0.0.1:7001 oracle@<server>
  #     danach im Browser des Admin-PCs: http://localhost:7001/em
  #     Dann kann /em in Nginx komplett gesperrt werden (SCHRITT 2.2).

  # 2.1 Server-Version verbergen und Sicherheits-Header setzen - im
  #     "server { listen 443 ssl; ... }"-Block oben einfuegen:
  #
  #     server_tokens off;
  #     add_header Strict-Transport-Security "max-age=31536000" always;
  #     add_header X-Content-Type-Options    "nosniff"          always;
  #     add_header X-Frame-Options           "SAMEORIGIN"       always;
  #
  #   Achtung: Steht in einer location ein eigenes "add_header", gelten dort
  #   die Header des server-Blocks NICHT (Nginx-Verhalten) - betrifft hier
  #   nur /nginx-health, das ist unkritisch.
  #   HSTS (Strict-Transport-Security) erst setzen, wenn das Zertifikat
  #   dauerhaft gueltig ist - Browser merken sich die Einstellung 1 Jahr.

  # 2.2 /console und /em
  #   - /console gibt es in WebLogic 14.1.2 nicht mehr: den location-Block
  #     "location /console { ... }" loeschen.
  #   - /em: entweder ganz entfernen (Zugriff nur per SSH-Tunnel, 1.3) oder
  #     auf die IP-Adressen der Administratoren beschraenken - NICHT ein
  #     ganzes 10.0.0.0/8-Netz:
  #
  #     location /em {
  #         allow 10.1.2.10;      # Admin-PC 1
  #         allow 10.1.2.11;      # Admin-PC 2
  #         deny  all;
  #         proxy_pass http://wls_admin;
  #     }

  # 2.3 Reports-Verwaltungsbefehle (Web Commands) von aussen sperren.
  #     Diese Befehle zeigen Umgebung, Jobs, Server-Interna (showenv zeigt
  #     z.B. alle Umgebungsvariablen des Servers) oder brechen Jobs ab
  #     (killjobid). Normale Berichtsaufrufe (/reports/rwservlet?report=...)
  #     sind davon NICHT betroffen. VOR "location /reports/ { ... }"
  #     einfuegen:
  #
  #     location ~* ^/reports/rwservlet/(showenv|showmap|showjobs|showjobid|showmyjobs|killjobid|getjobid|getserverinfo|showauth|delauth|parsequery|help) {
  #         allow 127.0.0.1;
  #         # allow <IP des Monitoring-Servers>;
  #         deny  all;
  #         proxy_pass http://wls_reports;
  #     }
  #
  #   Monitoring auf dem Server selbst ruft http://localhost:9002/...
  #   direkt auf und ist von dieser Sperre nicht betroffen.

  nginx -t && systemctl reload nginx

  # Kontrolle (von einem anderen Rechner aus):
  #   curl -sI https://<fqdn>/reports/rwservlet/showenv       -> 403
  #   curl -sI https://<fqdn>/em                              -> 403 (ausser Admin-IP)
  #   curl -sI https://<fqdn>/ | grep -i -E "server:|strict-transport"
  #     -> "Server: nginx" ohne Versionsnummer, HSTS-Header vorhanden

SCHRITT 7: Reports-Server-Administrator <identifier>  (als oracle)
================================================================================

  # In rwserver.conf legt <identifier> den Administrator DES REPORTS-
  # SERVERS fest (kein WebLogic-Benutzer). Er wird gebraucht fuer:
  #   - getserverinfo / showjobs, solange der Reports-Server nicht
  #     abgesichert ist (SCHRITT 7b; sonst REP-52262 "Diagnostic output is
  #     disabled", bestaetigt 2026-10-15)
  #   - das Stoppen/Verwalten des Servers ueber Web-Befehle
  #   - als Notfallzugang, auch bei abgesichertem Server (getestet)
  # Ist der Eintrag auskommentiert oder leer, ist das Verhalten nicht
  # geprueft (offener Test) - daher IMMER mit eigenem Kennwort setzen.

  cp $RWSERVER_CONF ${RWSERVER_CONF}.bak_$(date +%Y%m%d_%H%M%S)
  vi $RWSERVER_CONF
  #   Den (ggf. auskommentierten) identifier-Eintrag ersetzen durch:
  #     <identifier encrypted="no">repadmin/<KENNWORT></identifier>
  #   Position: direkt nach </folderAccess>.
  #   Das Kennwort steht nur bis zum naechsten Start im Klartext - der
  #   Reports-Server verschluesselt es dabei selbst (danach
  #   encrypted="yes"). Kennwort im Passwort-Safe ablegen - es laesst sich
  #   aus der Datei NICHT zurueckgewinnen.

BEKANNTE PROBLEME UND LOESUNGEN
================================================================================

  Problem: getserverinfo liefert "REP-52262 Diagnostic output is disabled",
           auch mit authid=monUser oder authid=<WebLogic-Admin>
  Ursache: Reports-Server ist nicht abgesichert - dann gilt fuer
           Web-Befehle nur der Reports-Server-Administrator aus <identifier>
  Loesung: SCHRITT 7b (dann monUser), oder authid=repadmin/<KENNWORT>
           (SCHRITT 7)

  Problem: nach securityId "REP-50171 Authentication failed" fuer alle,
           Berichte laufen nicht, im Log "user ... does not exist"
  Ursache: Identity Store des Reports-Servers noch XML (9.7b fehlt)
  Loesung: Reports_kochbuch_de.txt 9.7b, Reports-Server neu starten

  Problem: erste Anmeldung nach einem Start dauert Minuten
  Ursache: JDK-Thread "process reaper" stuerzt ab (StackOverflowError im
           repServer01.out) / veraltete Adresse im rwservlet (60 s)
  Loesung: Reports_kochbuch_de.txt 9.9 (REPORTS_JVM_OPTIONS) und 9.9b
           (setUserOverrides.sh)

  Problem: Aufruf ueber getserverinfo?autid=... bzw. Kennwort mit "#"
  Ursache: Tippfehler (authid) bzw. "#" beendet in einer URL den Teil, der
           zum Server geht
  Loesung: authid=; Sonderzeichen URL-codieren (# = %23) oder
           curl --data-urlencode verwenden

  Problem: Anmeldung am EM schlaegt fehl, obwohl das Kennwort stimmt
  Ursache: Konto durch die Kontosperre gesperrt (5 Fehlversuche, z.B. durch
           ein Skript mit altem Kennwort)
  Loesung: 30 Minuten warten oder mit einem anderen Administrator anmelden;
           Ursache (Skript/Monitoring/Autostart) beseitigen, SCHRITT 13

  Problem: createUser bricht mit einer Meldung zur Kennwort-Validierung ab
  Ursache: Kennwort erfuellt die Richtlinie aus SCHRITT 4 nicht
  Loesung: laengeres Kennwort mit Gross-/Kleinbuchstaben, Ziffer,
           Sonderzeichen, ohne den Benutzernamen

  Problem: cd('/SecurityConfiguration/...') meldet AttributeNotFoundException
  Ursache: nach OPSS-Befehlen (grantAppRole ...) steht WLST im
           domainRuntime-Baum
  Loesung: serverConfig() eingeben, dann erneut cd(...)

  Problem: nach singlesignon=yes laufen Berichte aus der Anwendung nicht
           mehr (Anmeldeseite / 401)

  Loesung: Aufruf ueber cmdkey=<schluessel> umstellen oder vorerst
