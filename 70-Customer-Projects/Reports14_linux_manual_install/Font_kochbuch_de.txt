VORAUSSETZUNGEN
--------------------------------------------------------------------------------

  Oracle Reports kennt ZWEI Font-Mechanismen:
    1. PDF-Ausgabe (desformat=pdf): uifont.ali + TrueType-Fonts in
       REPORTS_FONT_DIRECTORY (Teil A, Schritte 1-7)
    2. HTML-Ausgabe / HTML-Parameterformular: "screen printer"
       (screenprinter.ppd + AFM-Metrikdateien, Teil B, Schritt 8)
  Liegen die Original-Schriften als TTF auf dem Server (z.B. arial.ttf aus
  Windows), reicht fuer das PDF Teil A - so beim Kunden.
  ABER bei ERSATZSCHRIFTEN (keine arial.ttf auf dem Server, Arial wird auf
  Liberation Sans abgebildet) braucht auch das PDF Teil B: ohne AFM-Datei
  wird die Schrift im PDF zu "Symbol" (Type 1, griechische Zeichen).
  Getestet am 2026-10-19 (Testsystem, rwrun und Reports Server, ohne
  AFM-Dateien):
    - eigene TTF mit Familie "Arial", ohne [Global]-Alias -> eingebettet
    - dieselbe TTF, aber "Arial = helvetica" in [Global]   -> Symbol
    - nur Ersatzschriften (Liberation/DejaVu) fuer Arial, Helvetica,
      Times New Roman, Courier New, Tahoma                -> Symbol
    - NLS_LANG AL32UTF8 oder WE8MSWIN1252                 -> kein Unterschied
  Mit Schritt 8 und den Eintraegen aus Schritt 4 wurden alle Ersatzschriften
  eingebettet. Empfehlung: Teil B immer mit einrichten (schadet nicht);
  Reihenfolge Schritte 1-5, Schritt 8, Neustart (6), Test (7).

  Alle Schritte laufen als oracle-User, ausser Schritt 1 und 8.2 (root,
  nur Paketinstallation).

  4.2 Eintraege anlegen bzw. pruefen
  ----------------------------------------------------------------------------
  # [PDF:Subset]-Eintraege fuer die Standard-Ersatzschriften anlegen bzw.
  # pruefen. KRITISCHE SYNTAX - rechte Seite IMMER in Anfuehrungszeichen,
  # IMMER mit .ttf-Erweiterung:
  #   "Arial"..         = "LiberationSans-Regular.ttf"   <- richtig
  #   "Arial"...Bold    = "LiberationSans-Bold.ttf"       <- richtig
  #   Arial..           = LiberationSans-Regular.ttf      <- FALSCH (keine Anfuehrungszeichen)
  #   "Arial"..         = "LiberationSans-Regular"        <- FALSCH (kein .ttf)
  # Spezifischere Eintraege (mit Italic/Bold-Qualifier) MUESSEN vor dem
  # generischen ".."-Eintrag stehen.
  #
  # Benoetigte Eintraege (am Testsystem nachgewiesen, 2026-10-19):
  #   - je Ersatzschrift die FAMILIE mit Qualifier, z.B. "Helvetica"..,
  #     "Courier".. und auch "Times".. - [Global] macht aus
  #     "Times New Roman" die Familie "times"; ohne "Times"..-Eintraege
  #     bleibt Times eine nicht eingebettete Type-1-Schrift
  #   - die Linux-Schriften unter ihrem eigenen Namen, falls Reports sie
  #     direkt verwenden: "LiberationSans".. / "Liberation Sans".. usw.,
  #     "DejaVuSans".. / "DejaVu Sans"..
  #   - in [Global] fuer Schriften ohne eigene AFM-Datei einen Alias auf
  #     eine Familie mit AFM, z.B.
  #       Tahoma  = DejaVuSans
  #       Verdana = DejaVuSans
  #     (ohne Alias wurde Tahoma zu Courier)
  # Die vollstaendige, getestete Datei erzeugt IHateWeblogic mit
  # 04-ReportsFonts/uifont_ali_update.sh - sie kann von dort uebernommen
  # werden (Vorlage: 04-ReportsFonts/uifont_ali_template.ali).

  grep -A 30 '\[PDF:Subset\]' "$UIFONT_ALI"
  # Erwartet: die Eintraege wie oben beschrieben

  ----------------------------------------------------------------------------
  4.3 Syntax pruefen mit mfontchk
  ----------------------------------------------------------------------------

  export LD_LIBRARY_PATH="${ORACLE_HOME}/lib"

  # mfontchk braucht nur die Bibliotheken aus $ORACLE_HOME/lib (libuimotif

  HTML-Parameterformular - und bei Ersatzschriften (siehe
  VORAUSSETZUNGEN) auch im PDF. URSACHE: Das Parameterformular nutzt den
  "screen printer" (screenprinter.ppd + AFM-Dateien). Ohne passende
  AFM-Datei faellt Reports auf *DefaultFont (Courier) oder - bei
  Zeichensatzkonflikt - auf Symbol zurueck.

  echo "OH_AFM=$OH_AFM AFM_DIR=$AFM_DIR"
  # Erwartet: beide gefuellt. LEER? -> SCHRITT 0

  # Erwartet: beide gefuellt. LEER? -> SCHRITT 0

  ----------------------------------------------------------------------------
  8.1 FontSpecific-Kopien der Standard-AFMs
  ----------------------------------------------------------------------------
  # EncodingScheme FontSpecific umgeht die NLS_LANG-Zeichensatzpruefung,
  # die sonst AdobeStandardEncoding-Schriften ablehnt (MOS Doc ID 300416.1).
  # Der Oracle-Home-Ordner selbst wird dabei NIE veraendert, nur in den
  # Domain-eigenen Ordner kopiert.

  mkdir -p "$AFM_DIR"

  for f in "$OH_AFM"/Helvetica* "$OH_AFM"/Courier* "$OH_AFM"/Times*; do
      sed 's/^EncodingScheme .*/EncodingScheme FontSpecific/' "$f" > "$AFM_DIR/$(basename "$f")"
  done

  grep -H '^EncodingScheme' "$AFM_DIR"/Helvetica* "$AFM_DIR"/Courier* "$AFM_DIR"/Times* 2>/dev/null
  # Erwartet: jede Zeile endet mit "EncodingScheme FontSpecific"

  ----------------------------------------------------------------------------

  ----------------------------------------------------------------------------

  ----------------------------------------------------------------------------
  8.3 Je Zeichensatz/Stil eine AFM-Datei generieren  (wieder als oracle)
  ----------------------------------------------------------------------------

  # -Italic / -BoldItalic. HIER die konkreten TTF-Dateinamen aus
  # $REPORTS_FONT_DIR einsetzen - Beispiel fuer eine Arial-Ersatzschrift
  # (je Datei ein Befehl):
  #
  #   python3 $AFM_PY "$FONT_DIR/arial.ttf"    "Arial"            -o "$AFM_DIR/Arial"
  #   python3 $AFM_PY "$FONT_DIR/arialbd.ttf"  "Arial-Bold"       -o "$AFM_DIR/Arial-Bold"
  #   python3 $AFM_PY "$FONT_DIR/ariali.ttf"   "Arial-Italic"     -o "$AFM_DIR/Arial-Italic"
  #   python3 $AFM_PY "$FONT_DIR/arialbi.ttf"  "Arial-BoldItalic" -o "$AFM_DIR/Arial-BoldItalic"
  #
  # --encoding (Standard: cp1252/WE8MSWIN1252) MUSS zum NLS_LANG-Zeichensatz
  # aus rwserver.conf passen (siehe Reports_kochbuch_de.txt Schritt 9.7):
  #   WE8ISO8859P15 -> --encoding iso8859-15
  #   AL32UTF8      -> kein 1-Byte-Encoding passt hier sauber, siehe
  #                    "Bekannte Probleme" unten

  # Jede generierte AFM-Datei sofort pruefen:

  python3 $AFM_PY --check "$AFM_DIR/Arial-Bold"
  # Erwartete Ausgabe: "OK <Dateiname>" mit CapHeight/XHeight != 0,
  # EncodingScheme FontSpecific, FontName == Dateiname, FullName ohne
  # Sonderzeichen (z.B. "Arial Bold", NICHT lokalisiert wie "Arial Gras")

  ----------------------------------------------------------------------------
  8.4 *Font-Zeilen in screenprinter.ppd ergaenzen
  ----------------------------------------------------------------------------
  TS=$(date +%Y%m%d_%H%M%S)

  cp -p "$PPD" "${PPD}.bak_$TS"

  echo "${PPD}.bak_$TS" > $WORK/08_ppd_backup.txt

  # Fuer jeden neu generierten Schluessel pruefen, ob er schon existiert,
  # und falls nicht nach der letzten bestehenden *Font-Zeile einfuegen.
  # Beispiel fuer den Schluessel Arial-Bold - die Befehle von KEY= bis
  # zur Kontrolle fuer jeden weiteren Schluessel (Arial, Arial-Italic,
  # Arial-BoldItalic, ...) wiederholen.

  KEY="Arial-Bold"

  grep -c "^\*Font ${KEY}:" "$PPD"
  # 1 (oder mehr) -> Schluessel ist schon da, naechster Schluessel
  # 0             -> die naechsten vier Befehle ausfuehren

  LAST_LINE=$(grep -n '^\*Font ' "$PPD" | tail -1)

  LAST_LINE=${LAST_LINE%%:*}

  echo "letzte *Font-Zeile: $LAST_LINE"
  # Erwartet: eine Zeilennummer. LEER -> NICHT weiter (sed wuerde sonst
  # falsch einfuegen), PPD pruefen.

  sed -i "${LAST_LINE}a *Font ${KEY}: Standard \"(001.000)\" Standard ROM" "$PPD"

  grep -n "^\*Font ${KEY}:" "$PPD"
  # Erwartet: genau eine Zeile
  #   *Font Arial-Bold: Standard "(001.000)" Standard ROM

  # Zurueck, falls noetig:
  #   cp -p "$(cat $WORK/08_ppd_backup.txt)" "$PPD"

  ----------------------------------------------------------------------------
  8.5 Nur den Report-Engine-Prozess neu starten
  ----------------------------------------------------------------------------
  # WICHTIG: NICHT den ganzen Reports-Server neu starten - AFM/PPD werden
  # nur beim Start eines Engine-Prozesses gelesen, der Reports-Server
  # selbst startet den Engine-Prozess danach automatisch neu (minEngine).

  # ALLE Engines beenden: jede Engine (rwEng-0, rwEng-1 ... bei minEngine=2)
  # liest AFM/PPD nur bei ihrem eigenen Start. Laufende Berichte brechen ab -
  # nur zu einer ruhigen Zeit (vorher: showjobs bzw. status.sh).

  pgrep -af 'RWEngine name=rwEng'
  # Erwartet: die laufenden Engines, z.B. ... RWEngine name=rwEng-0 ...
  #           und ... name=rwEng-1 ...

  ENG_PIDS=$(pgrep -f 'RWEngine name=rwEng')

  echo "Engine-PIDs: $ENG_PIDS"
  # Erwartet: eine Zahl je Engine. LEER -> keine Engine, nichts zu tun

  kill -TERM $ENG_PIDS

  pgrep -af 'RWEngine name=rwEng'
  # Erwartet (nach einigen Sekunden): wieder so viele Engines wie
  # minEngine, alle mit neuer PID

  ----------------------------------------------------------------------------
  8.6 Verifikation
  ----------------------------------------------------------------------------
  # Im Browser das Parameterformular aufrufen und pruefen:
  #   - Seitenquelltext: face="arial" (oder der verwendete Fontname) ist
  #     vorhanden, kein Darstellungsfehler
  #   - Sonderzeichen (grosse Umlaute A/O/U mit Punkten, scharfes s,
  #     Euro-Zeichen) werden korrekt angezeigt

  pdffonts /tmp/test_report.pdf
  # Erwartet: jetzt "CID TrueType ... yes yes" fuer alle Schriften
  # (siehe Schritt 7)

BEKANNTE PROBLEME UND LOESUNGEN
================================================================================

  Problem: mfontchk zeigt '^' rechts neben dem Font-Namen
  Ursache: TTF-Datei nicht in REPORTS_FONT_DIRECTORY
  Loesung: ls "$REPORTS_FONT_DIR" | grep -i liberation
           Dateiname in uifont.ali muss EXAKT mit dem Dateinamen uebereinstimmen.

  Problem: PDF zeigt "Symbol  Type 1  no no no" (Text als griechische
           Zeichen)
  Ursache: Ersatzschrift (z.B. Arial -> Liberation Sans) ohne AFM-Datei im
           "screen printer" - Schritt 8 fehlt, oder die Engines wurden
           danach nicht neu gestartet. (Eine Schrift mit eigener TTF ohne
           [Global]-Alias waere davon nicht betroffen.)
  Loesung: Schritt 8 durchfuehren, Reports Server neu starten (Schritt 6)

  Problem: PDF zeigt eine Schrift als Type 1 ohne Einbettung (z.B.
           Times-Roman, LiberationSans)
  Ursache: Schrift gefunden, aber kein [PDF:Subset]-Eintrag fuer ihre
           Familie ("Times"..), oder REPORTS_FONT_DIRECTORY fehlt in der
           Umgebung der ENGINES
  Loesung: Schritt 4 (Familien-Eintraege), Schritt 6 Kontrolle (Engines,
           nicht WLS_REPORTS), Reports Server neu starten

  Problem: uifont.ali Syntaxfehler
  Loesung: [PDF:Subset]-Eintraege muessen lauten:
             "FontName"..       = "dateiname.ttf"
             "FontName"...Bold  = "dateiname-Bold.ttf"
           Rechte Seite IMMER in Anfuehrungszeichen, IMMER mit
           .ttf-Erweiterung.

  Problem: Parameterformular zeigt griechische/Symbol-Zeichen
  Ursache: Schritt 8 (AFM/PPD) fehlt - Teil A reicht fuer das
           Parameterformular nicht
  Loesung: Schritt 8 vollstaendig durchfuehren

  Problem: ttf2reports_afm.py --check meldet "FullName enthaelt
           nicht-ASCII-Zeichen" / lokalisierter Name (z.B. "Arial Gras"
           statt "Arial Bold")
  Ursache: TTF-Datei hat keinen englischen Namenseintrag, oder ein
           lokalisierter Eintrag wurde gewaehlt
  Loesung: Andere/aktuellere TTF-Version verwenden, oder --check-Hinweis
           als bekannte Einschraenkung akzeptieren (rein ASCII-basierte
           lokalisierte Namen wie "Arial Gras" werden nicht automatisch
           erkannt - Ergebnis manuell pruefen)

  Problem: CapHeight/XHeight = 0 in der generierten AFM-Datei
  Ursache: TTF hat keine modernen OS/2-Metrikfelder
  Loesung: ttf2reports_afm.py leitet in diesem Fall die Werte aus den
           Zeichen-Bounding-Boxen von "H"/"x" ab - meist bereits
           automatisch geloest; bei 0 trotzdem: andere TTF-Datei pruefen

  Problem: Falsche Zeichen bei AL32UTF8 (Unicode) als NLS_LANG
  Ursache: Das AFM-Format bildet pro Byte genau EIN Zeichen ab - UTF-8 ist
           aber mehrbytig, ein 1-Byte-Encoding kann das grundsaetzlich
           nicht sauber abbilden
  Loesung: Keine allgemeingueltige Loesung bekannt - dies ist ein noch
           offener Testpunkt, siehe
           04-ReportsFonts/HTML_ParameterForm_Fonts.md Abschnitt 9
           (Caveats and Open Points)

  Problem: Neustart ueber systemctl schlaegt fehl ("Unit ... not found")
  Ursache: Der Dienst heisst nach Autostart_linux_middleware.txt
           "reportrpgpi" (nicht "weblogic"); ohne Autostart gibt es keinen
  Loesung: systemctl list-units | grep -i report - sonst nur den
           Reports-Server mit stopComponent.sh / startComponent.sh neu
           starten (Schritt 6).
