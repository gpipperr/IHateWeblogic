================================================================================
  WebLogic / Reports starten und stoppen - einfachste Variante
  (Zwei eigene Skripte, OHNE IHateWeblogic-Skripte/Lib als Abhaengigkeit)
================================================================================
  Zielgruppe : Kunde / Betrieb, der den Server selbst hoch- und runterfahren
               moechte, ohne sich mit WebLogic-Details zu beschaeftigen
  Umgebung   : Oracle Linux 9, FMW 14.1.2.0.0, WebLogic 14.1.2, nur Reports
  Erstellt   : 2026-10, ueberarbeitet 2026-11-04 (Stil nach
               70-Customer-Projects/cookbook-Skill.md)
  Voraussetzung: Reports_kochbuch_de.txt vollstaendig durchgefuehrt (Domain
                 angelegt, AdminServer/Managed Server/Reports-Komponenten
                 laufen mindestens einmal erfolgreich)

  WICHTIG: Diese beiden Skripte stoppen bzw. starten IMMER ALLES zusammen,
  in der richtigen Reihenfolge - keine Einzelsteuerung einzelner
  Komponenten. Das ist fuer den Anfang bewusst so einfach gehalten.

  Hinweis zur externen Datenbank: Die Datenbank laeuft NICHT auf dieser
  Maschine (externe, bereits bestehende DB - siehe Reports_kochbuch_de.txt).
  Dieses Kochbuch muss sich um die Datenbank daher nicht kuemmern.

  Parameter  : Alle Pfade, Namen und Ports der Kochbuecher stehen in EINER
               Datei /u01/oracle/tools/patch_install.ini (Vorlage:
               patch_install.ini neben diesem Kochbuch). EINMALIG genau an
               die eigene Umgebung anpassen, dann in JEDER neuen Sitzung
               laden:

                 . /u01/oracle/tools/set_script_env.sh

               PATH, wlst und den Wechsel zwischen den Homes setzt setdb
               (~/.bashrc.d/ihw_env.sh) - beides richtet der Fahrplan ein.
               Die Parameter im Text bleiben zur Nachvollziehbarkeit stehen
               (gleiche Namen wie in patch_install.ini).
               Fahrplan: ../Start_beim_Kunden_kochbuch_de.txt
================================================================================

VORAUSSETZUNGEN
--------------------------------------------------------------------------------
  Alle Schritte laufen als oracle-User.

  Die folgenden Werte muessen zu der Domain passen, die mit
  Reports_kochbuch_de.txt angelegt wurde (siehe dortige VORAUSSETZUNGEN,
  gleiche Namen wie in patch_install.ini):

    ORACLE_HOME             /u01/oracle/fmw
    DOMAIN_HOME             /u01/user_projects/domains/reportRpgpi
    WLS_MANAGED_SERVER      WLS_REPORTS
    WLS_ADMIN_URL           t3://localhost:7001
    REPORTS_SERVER_NAME     repServer01

  Was wo landet:

    /u01/oracle/tools/patch_install.ini die Werte (Fahrplan Schritt 3) -
                                        nur lesen (SCHRITT 1)
    /u01/oracle/tools/start_wls_all.sh  <- SCHRITT 2 (Rechte 755), neben
    /u01/oracle/tools/stop_wls_all.sh   <- SCHRITT 3  der ini; NICHT im
                                        ORACLE_HOME (ein Restore des Homes
                                        braechte alte Skripte zurueck)
    $DOMAIN_HOME/bin/                   die Oracle-Skripte (Teil der Domain,
                                        nichts zu kopieren - Tabelle SCHRITT 0)
    $DOMAIN_HOME/nodemanager/nm_start.log   <- Start Node Manager (0.1 / 2)
    /tmp/adminserver_start.log          <- Start AdminServer (0.1 / 2)
    /tmp/managed_start.log              <- Start Managed Server (0.1 / 2)
    $DOMAIN_HOME/config/fmwconfig/ovd/default/   ($OVD_DIR, 0.0)
      ovd.lok -> ovd.lok.stale          libOVD-Sperre, vor jedem
                                        AdminServer-Start zur Seite (0.1 / 2)
    ~/oracle-WebLogicConfig.properties  nur nach "storeUserConfig" (0.1):
    ~/oracle-WebLogicKey.properties     gespeichertes Node-Manager-Kennwort

  Kennwoerter: in dieser Anleitung stehen Platzhalter wie
  <IDENTIFIER_PASSWORD>. Kennwoerter werden NIE in die Befehlszeile
  getippt, sondern verdeckt mit "read -s" abgefragt. Aufrufe an rwservlet
  mit authid= immer per POST (curl -d / --data-urlencode, nichts in der
  URL) - sonst steht das Kennwort im Klartext im access.log von
  WLS_REPORTS.


================================================================================
SCHRITT 0: Die mitgelieferten Oracle-Skripte - manuell starten, Status
           abfragen, stoppen  (als oracle)
================================================================================

  # Oracle liefert im Domain-Verzeichnis unter $DOMAIN_HOME/bin/ fertige
  # Start-/Stop-Skripte mit. Mit ihnen laesst sich jede Komponente einzeln
  # von Hand bedienen - z.B. zur Fehlersuche oder wenn nur ein Teil neu
  # gestartet werden soll. Die Skripte aus Schritt 2/3 rufen genau diese
  # Oracle-Skripte auf.
  #
  #   Komponente          Starten                     Stoppen
  #   ------------------  --------------------------  ---------------------------
  #   1. Node Manager     startNodeManager.sh         stopNodeManager.sh
  #   2. AdminServer      startWebLogic.sh            stopWebLogic.sh
  #   3. Managed Server   startManagedWebLogic.sh     stopManagedWebLogic.sh
  #      (Reports-WLS)    <server> <admin-url>        <server> <admin-url> <user> <pw>
  #   4. Reports Server   startComponent.sh <name>    stopComponent.sh <name>
  #      (repServer01)    (laeuft ueber den Node Manager)
  #
  # Neustart des Reports Servers: stopComponent.sh, dann startComponent.sh.
  # restartComponent.sh gibt es zwar, fuer den Reports Server lehnt der Node
  # Manager es aber ab: "Server softRestart command is not supported on
  # ReportsServerComponent server" (bestaetigt 2026-10-15).
  #
  # Fertige Status-/Log-Skripte fuer den Betrieb (Ports, Prozesse, Node-
  # Manager-Status, Fehler in den Logs): Tools_status_logs_kochbuch.txt
  # (/u01/oracle/tools/status.sh, show_errors.sh, show_all_logs.sh).
  #
  # Ein eigenes Status-Skript liefert Oracle in 14.1.2 NICHT mit - der
  # Zustand wird unten per curl/ps abgefragt.

  # WICHTIG, falls der Autostart (Autostart_linux_middleware.txt) schon
  # eingerichtet ist: die Umgebung dann NUR noch ueber "systemctl start/stop"
  # bedienen und nicht zusaetzlich mit den Befehlen hier - sonst kennt der
  # Node Manager den Zustand der von Hand gestarteten Server nicht.

  ----------------------------------------------------------------------------
  0.0 Variablen setzen und pruefen  (in JEDEM neuen Terminal)
  ----------------------------------------------------------------------------
  # Kurzweg mit patch_install.ini:

  . /u01/oracle/tools/set_script_env.sh

  # Ohne set_script_env.sh - Werte fuer die aktuelle Sitzung von Hand:
  #   export DOMAIN_HOME=/u01/user_projects/domains/reportRpgpi
  #   export WLS_MANAGED_SERVER=WLS_REPORTS
  #   export WLS_ADMIN_URL=t3://localhost:7001
  #   export WLS_REPORTS_PORT=9002
  #   export REPORTS_SERVER_NAME=repServer01

  echo "DH=$DOMAIN_HOME MS=$WLS_MANAGED_SERVER URL=$WLS_ADMIN_URL REP=$REPORTS_SERVER_NAME"
  # Erwartet: alle vier gefuellt. LEER? -> set_script_env.sh bzw. exports oben

  OVD_DIR=$DOMAIN_HOME/config/fmwconfig/ovd/default

  RW_URL=http://localhost:$WLS_REPORTS_PORT/reports/rwservlet

  echo "$RW_URL"

  # Erwartet: http://localhost:9002/reports/rwservlet. Port LEER ->
  # export WLS_REPORTS_PORT=9002

  cd $DOMAIN_HOME/bin

  ----------------------------------------------------------------------------
  0.1 Starten  (in dieser Reihenfolge)
  ----------------------------------------------------------------------------
  # 1. Node Manager - zuerst, wie in start_wls_all.sh und im Autostart

  nohup ./startNodeManager.sh > $DOMAIN_HOME/nodemanager/nm_start.log 2>&1 &

  # ca. 10 Sekunden, Kontrolle 0.2 Punkt 2

  # 2. AdminServer - braucht $DOMAIN_HOME/servers/AdminServer/security/
  #    boot.properties (Reports_kochbuch_de.txt Schritt 4). Ohne diese Datei
  #    bricht ein Start im Hintergrund (nohup) sofort ab: im Production Mode
  #    gibt es keine Konsole fuer die Passwortabfrage (BEA-090782).
  #    Vorher die libOVD-Sperre entfernen, die der Reports-Server liegen
  #    laesst - sonst findet der EM unter "Principal hinzufuegen" keine
  #    Benutzer (Reports_security.txt, Bekannte Probleme):

  mv -f $OVD_DIR/ovd.lok $OVD_DIR/ovd.lok.stale 2>/dev/null
  # Erwartet: keine Ausgabe (auch dann, wenn keine Sperre da war)

  nohup ./startWebLogic.sh > /tmp/adminserver_start.log 2>&1 &

  # ca. 1 Minute warten, bis der Status (0.2, Punkt 1) "200" meldet

  # 3. Managed Server - braucht ebenfalls boot.properties
  #    (Reports_kochbuch_de.txt Schritt 6) und einen laufenden AdminServer

  nohup ./startManagedWebLogic.sh $WLS_MANAGED_SERVER $WLS_ADMIN_URL > /tmp/managed_start.log 2>&1 &

  # ca. 1 Minute warten, bis der Status (0.2, Punkt 3) "200" meldet

  # 4. Reports Server - wird ueber den Node Manager gestartet, der muss
  #    also laufen. Laeuft im Vordergrund.

  ./startComponent.sh $REPORTS_SERVER_NAME
  # Erwartet am Ende: "Successfully started server ..."
  # "Connection refused ... 5556" heisst: Node Manager laeuft nicht -> erst
  # Punkt 2 (Node Manager starten).

  # Fragt das Skript nach dem Node-Manager-Passwort: den Benutzer liest es
  # aus der Domain, nachsehen mit

  grep -o "<node-manager-username>[^<]*" $DOMAIN_HOME/config/config.xml
  # "weblogic"                     -> WebLogic-Admin-Passwort eingeben
  # eine zufaellige Zeichenkette   -> Passwort ist unbekannt, siehe
  #                                   Autostart_linux_middleware.txt
  #                                   Schritt 1b (per WLST auf den
  #                                   Administrator setzen)

  # Einmalig speichern (danach keine Abfrage mehr; legt
  # ~/oracle-WebLogicConfig.properties + ~/oracle-WebLogicKey.properties an):
  #   ./startComponent.sh $REPORTS_SERVER_NAME storeUserConfig

  ----------------------------------------------------------------------------
  0.2 Zustand der 4 Komponenten abfragen
  ----------------------------------------------------------------------------
  # 1. AdminServer

  curl -s -o /dev/null -w "%{http_code}\n" http://localhost:7001/weblogic/ready
  # Erwartet: 200 (503 = startet noch)

  # 2. Node Manager

  ss -ltn | grep ':5556'
  # Erwartet: eine LISTEN-Zeile auf Port 5556

  ps -ef | grep '[w]eblogic.NodeManager'
  # Erwartet: ein Java-Prozess "weblogic.NodeManager"

  # 3. Managed Server

  curl -s -o /dev/null -w "%{http_code}\n" http://localhost:9002/weblogic/ready
  # Erwartet: 200 (503 = startet noch)

  # 4. Reports Server - Prozess vorhanden?

  ps -ef | grep "[r]wserver server=$REPORTS_SERVER_NAME"
  # Erwartet: eine Zeile

  # Und antwortet er? authid ist der Server-Administrator aus <identifier>
  # in rwserver.conf (Reports_kochbuch_de.txt Schritt 9.7), NICHT ein
  # WebLogic-Benutzer. Kennwort verdeckt abfragen, Aufruf per POST:

  read -s -p "Kennwort des <identifier>-Admins repadmin: " APW

  echo

  curl -s -d server=$REPORTS_SERVER_NAME -d statusformat=XML --data-urlencode "authid=repadmin/$APW" $RW_URL/getserverinfo
  # Erwartet: <engineInstance ... status="1"> (1 = Engine bereit/IDLE,
  # 2 = beschaeftigt, 0 = tot). "REP-50001 The server is initializing"
  # = noch 1-2 Minuten warten.
  # Fehler: code="56071" = Benutzer nicht berechtigt, code="50171" =
  # Kennwort falsch.

  unset APW

  ----------------------------------------------------------------------------
  0.3 Stoppen  (umgekehrte Reihenfolge)
  ----------------------------------------------------------------------------
  # Reihenfolge: Reports Server -> Managed Server -> AdminServer -> Node
  # Manager. Der Node Manager kommt zuletzt, weil der Reports Server ueber
  # ihn gestoppt wird.

  # 4. Reports Server

  ./stopComponent.sh $REPORTS_SERVER_NAME

  # 3. Managed Server - braucht WebLogic-Benutzer und -Passwort. Das Passwort
  #    nicht direkt in die Befehlszeile tippen (steht sonst in der
  #    Shell-History), sondern verdeckt abfragen:

  read -s -p "WebLogic-Passwort: " WLS_PASS

  echo

  ./stopManagedWebLogic.sh $WLS_MANAGED_SERVER $WLS_ADMIN_URL weblogic "$WLS_PASS"

  # 1. AdminServer

  ./stopWebLogic.sh weblogic "$WLS_PASS" $WLS_ADMIN_URL

  unset WLS_PASS

  # 2. Node Manager

  ./stopNodeManager.sh

  # Kontrolle: alle Abfragen aus 0.2 liefern jetzt nichts mehr bzw.
  # "000" (keine Verbindung).

  TOOLS=/u01/oracle/tools

  # Schritt 1-3.


================================================================================
SCHRITT 2: start_wls_all.sh anlegen  (als oracle)
================================================================================

  # Das Skript wird mit einem Heredoc geschrieben - der ganze Block von
  # "cat" bis zur Zeile "EOF" ist EIN Befehl.

  cat > $TOOLS/start_wls_all.sh << 'EOF'
#!/bin/bash
# Startet Node Manager, AdminServer, Managed Server und den Reports-Server
# in dieser Reihenfolge. Einfachste Variante: immer alles zusammen
# starten, keine Einzelsteuerung.
#
# Werte (DOMAIN_HOME, WLS_MANAGED_SERVER, WLS_ADMIN_URL,
# REPORTS_SERVER_NAME) aus patch_install.ini im selben Verzeichnis.
set -a
. "$(dirname "$0")/patch_install.ini"
set +a

echo "=== 1/4 Node Manager starten ==="
nohup "$DOMAIN_HOME/bin/startNodeManager.sh" \
    > "$DOMAIN_HOME/nodemanager/nm_start.log" 2>&1 &
sleep 10

echo "=== 2/4 AdminServer starten ==="
# libOVD-Sperre des Reports-Servers entfernen (sonst EM-Benutzersuche leer)
mv -f "$DOMAIN_HOME/config/fmwconfig/ovd/default/ovd.lok" \
      "$DOMAIN_HOME/config/fmwconfig/ovd/default/ovd.lok.stale" 2>/dev/null
nohup "$DOMAIN_HOME/bin/startWebLogic.sh" \
    > /tmp/adminserver_start.log 2>&1 &
sleep 60

echo "=== 3/4 Managed Server ($WLS_MANAGED_SERVER) starten ==="
nohup "$DOMAIN_HOME/bin/startManagedWebLogic.sh" \
    "$WLS_MANAGED_SERVER" "$WLS_ADMIN_URL" \
    > /tmp/managed_start.log 2>&1 &
sleep 60

echo "=== 4/4 Reports-Server starten ==="
# Die Reports-Tools-Instanz ist reine Konfiguration (kein Prozess) - sie
# wird nicht gestartet (wie 01-Run/startStop.sh der Bibliothek)
"$DOMAIN_HOME/bin/startComponent.sh" "$REPORTS_SERVER_NAME"

echo
echo "Fertig. Logs bei Problemen:"
echo "  $DOMAIN_HOME/nodemanager/nm_start.log"
echo "  /tmp/adminserver_start.log"
echo "  /tmp/managed_start.log"
EOF

  chmod 755 $TOOLS/start_wls_all.sh

  ls -l $TOOLS/start_wls_all.sh
  # Erwartet: -rwxr-xr-x ... start_wls_all.sh


================================================================================
SCHRITT 3: stop_wls_all.sh anlegen  (als oracle)
================================================================================

  # WICHTIG: AdminServer/Managed Server lassen sich NICHT ohne
  # WebLogic-Benutzername und -Passwort stoppen - das Skript fragt beide
  # interaktiv ab (per "read"), speichert sie NIRGENDS und gibt das
  # Passwort beim Tippen nicht auf dem Bildschirm aus.
  # Der ganze Block von "cat" bis zur Zeile "EOF" ist EIN Befehl.

  cat > $TOOLS/stop_wls_all.sh << 'EOF'
#!/bin/bash
# Stoppt Reports-Server, Managed Server, AdminServer und Node Manager
# in umgekehrter Reihenfolge. Einfachste Variante: immer alles zusammen
# stoppen, keine Einzelsteuerung.
#
# Werte aus patch_install.ini im selben Verzeichnis.
set -a
. "$(dirname "$0")/patch_install.ini"
set +a

echo "Fuer AdminServer und Managed Server wird das WebLogic-Administrator-"
echo "Kennwort benoetigt (wird nirgends gespeichert)."
read -p "WebLogic-Benutzername [weblogic]: " WLS_USER
WLS_USER="${WLS_USER:-weblogic}"
read -s -p "WebLogic-Passwort: " WLS_PASS
echo

echo "=== 1/4 Reports-Server stoppen ==="
"$DOMAIN_HOME/bin/stopComponent.sh" "$REPORTS_SERVER_NAME"

echo "=== 2/4 Managed Server ($WLS_MANAGED_SERVER) stoppen ==="
"$DOMAIN_HOME/bin/stopManagedWebLogic.sh" \
    "$WLS_MANAGED_SERVER" "$WLS_ADMIN_URL" "$WLS_USER" "$WLS_PASS"

echo "=== 3/4 AdminServer stoppen ==="
"$DOMAIN_HOME/bin/stopWebLogic.sh" "$WLS_USER" "$WLS_PASS" "$WLS_ADMIN_URL"

echo "=== 4/4 Node Manager stoppen ==="
"$DOMAIN_HOME/bin/stopNodeManager.sh"

unset WLS_USER WLS_PASS
echo
echo "Fertig."
EOF

  chmod 755 $TOOLS/stop_wls_all.sh

  ls -l $TOOLS/stop_wls_all.sh
  # Erwartet: -rwxr-xr-x ... stop_wls_all.sh

  start_wls_all.sh

  # (liegt in /u01/oracle/tools - durch setdb im PATH)
  # Erwartet am Ende: "Fertig. Logs bei Problemen:" und die drei Log-Pfade

  ----------------------------------------------------------------------------

  ----------------------------------------------------------------------------
  RW_URL=http://localhost:$WLS_REPORTS_PORT/reports/rwservlet

  read -s -p "Kennwort des <identifier>-Admins repadmin: " APW

  echo

  curl -s -d server=$REPORTS_SERVER_NAME -d statusformat=XML --data-urlencode "authid=repadmin/$APW" $RW_URL/getserverinfo
  # Erwartet: XML-Antwort mit status="1" (Engine IDLE). Ohne authid kommt

  # Kennwort falsch.

  unset APW

  ----------------------------------------------------------------------------
  4.3 Alles stoppen  (fragt nach WebLogic-Benutzername/-Passwort)
  ----------------------------------------------------------------------------
  stop_wls_all.sh

  # Erwartet am Ende: "Fertig."

================================================================================
BEKANNTE PROBLEME UND LOESUNGEN
================================================================================

  Problem: stop_wls_all.sh bricht mit "No valid username/password or
           userConfigFile/userKeyFile provided" ab
  Ursache: falscher Benutzername/Passwort eingegeben, oder bei der
           Passwort-Abfrage aus Versehen Enter ohne Eingabe gedrueckt, ODER
           das WebLogic-Passwort enthaelt ein Leerzeichen (Oracles eigenes
           stopManagedWebLogic.sh reicht Benutzername/Passwort intern nicht
           in Anfuehrungszeichen weiter - das ist eine Einschraenkung im
           Oracle-Skript selbst, nicht in start_wls_all.sh/stop_wls_all.sh)
  Loesung: Skript erneut ausfuehren, Benutzername/Passwort sorgfaeltig
           eintippen (das Passwort wird beim Tippen nicht angezeigt - das
           ist normal, nicht nochmal tippen); enthaelt das WebLogic-Passwort
           ein Leerzeichen, ein neues Passwort ohne Leerzeichen vergeben

  Problem: start_wls_all.sh "ist fertig", aber getserverinfo antwortet
           nicht oder mit Fehler
  Ursache: 60 Sekunden Wartezeit reichen auf einer langsamen Maschine
           manchmal nicht
  Loesung: Noch 1-2 Minuten warten, dann den curl-Befehl aus Schritt 4.2
           erneut ausfuehren; bei weiterem Problem die drei Log-Dateien
           pruefen, die start_wls_all.sh am Ende auflistet

  Problem: Ein Server startet im Hintergrund (nohup) und ist kurz danach
           wieder weg; im Start-Log steht "BEA-090782 ... System Console
           ... was not found" und "shutDownStatus=255"
  Ursache: boot.properties fehlt fuer diesen Server - im Production Mode
           kann WebLogic ohne Konsole nicht nach dem Passwort fragen
  Loesung: boot.properties anlegen (Reports_kochbuch_de.txt Schritt 4 fuer
           den AdminServer, Schritt 6 fuer den Managed Server), neu starten

  Problem: getserverinfo antwortet mit "REP-52262 Diagnostic output is
           disabled"
  Ursache: authid fehlt oder ist ein WebLogic-Benutzer statt des
           Server-Administrators aus <identifier> in rwserver.conf
  Loesung: authid=repadmin/<IDENTIFIER_PASSWORD> verwenden (Schritt 0.2,
           per POST)

  Problem: Kennwort im access.log von WLS_REPORTS
  Ursache: rwservlet-Aufruf per GET mit authid= in der URL
           (".../getserverinfo?...&authid=...")
  Loesung: per POST aufrufen (curl -d / --data-urlencode, Schritt 0.2 /
           4.2)

  Problem: $DOMAIN_HOME ist leer, wenn man "echo $DOMAIN_HOME" eingibt
  Ursache: neue Sitzung, die Werte der ini sind noch nicht geladen
  Loesung: . /u01/oracle/tools/set_script_env.sh (Schritt 0.0) - die
           Skripte aus Schritt 2/3 lesen die ini selbst und brauchen das
           nicht

WEITERGEHENDE INFORMATIONEN
================================================================================

  Beide Skripte rufen ausschliesslich die von Oracle selbst mitgelieferten
  Start-/Stop-Skripte unter $DOMAIN_HOME/bin/ auf (startNodeManager.sh,
  startWebLogic.sh, startManagedWebLogic.sh, startComponent.sh und die
  jeweiligen "stop*"-Gegenstuecke) - keine Abhaengigkeit zu
  IHateWeblogic-Skripten oder deren Lib.

  Feinere Steuerung (einzelne Komponente starten/stoppen, Status-Tabelle
  aller Komponenten) bietet 01-Run/startStop.sh im IHateWeblogic-Repository
  - fuer den Anfang reichen die beiden Skripte hier aber aus.

  Naechstes Kochbuch: Autostart_linux_middleware.txt - automatischer
  Start/Stop beim Hoch- und Herunterfahren des Servers (systemd). Ab dann
  wird die Umgebung im Betrieb ueber "systemctl start/stop reportrpgpi"
  statt mit den beiden Skripten hier bedient.
