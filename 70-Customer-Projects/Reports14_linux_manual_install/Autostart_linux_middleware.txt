================================================================================
  WebLogic / Reports automatisch beim Systemstart starten (systemd)
  (Eigene Skripte + eine systemd-Unit, OHNE IHateWeblogic-Skripte/Lib)
================================================================================
  Zielgruppe : Kunde / Betrieb
  Umgebung   : Oracle Linux 9, FMW 14.1.2.0.0, WebLogic 14.1.2, nur Reports
  Erstellt   : 2026-10, Stil nach 70-Customer-Projects/cookbook-Skill.md
  Voraussetzung: Reports_kochbuch_de.txt vollstaendig durchgefuehrt, die
                 Umgebung laesst sich mit WLS_Report_start_stop_kochbuch.txt
                 von Hand starten und stoppen.

  Ziel: Nach einem Serverneustart starten alle Komponenten automatisch in
  der richtigen Reihenfolge, beim Herunterfahren werden sie sauber gestoppt.

    Start:  Node Manager - AdminServer - Managed Server - Reports-Komponenten
    Stop :  Reports-Komponenten - Managed Server - AdminServer - Node Manager

  Statt fester Wartezeiten (sleep) warten die Skripte, bis der jeweilige
  Server wirklich "RUNNING" meldet bzw. sein Prozess beendet ist - mit einer
  Obergrenze, damit ein haengender Server den Systemstart nicht blockiert.

  Hinweis zur externen Datenbank: Die Datenbank laeuft NICHT auf dieser
  Maschine - die Unit muss daher auf keine lokale Datenbank warten.

  Parameter  : Alle Pfade, Namen und Ports der Kochbuecher stehen in EINER
               Datei /u01/oracle/tools/patch_install.ini (Vorlage:
               patch_install.ini neben diesem Kochbuch). EINMALIG genau an
               die eigene Umgebung anpassen, dann in JEDER neuen Sitzung
               laden:

                 . /u01/oracle/tools/set_script_env.sh

               PATH, wlst und den Wechsel zwischen den Homes setzt setdb
               (~/.bashrc.d/ihw_env.sh) - beides richtet der Fahrplan ein.
               Die Parameter im Text bleiben zur Nachvollziehbarkeit stehen
               (gleiche Namen wie in patch_install.ini).
               Fahrplan: ../Start_beim_Kunden_kochbuch_de.txt
================================================================================

  # "Connection refused. Could not connect to NodeManager ... 5556"
  # (unabhaengig vom Passwort; beim Kunden so aufgetreten, 2026-10-15).

  # Keine Ausgabe -> Node Manager starten (die naechsten zwei Befehle):

  # ca. 10 Sekunden warten, dann:

  # fragt nur dessen Passwort ab:

  grep -o "<node-manager-username>[^<]*" $DOMAIN_HOME/config/config.xml

  #   - eine zufaellige Zeichenkette (z.B. "o2HTp584LE") -> das Passwort

  #     einmalig per WLST auf die Admin-Zugangsdaten setzen (AdminServer
  #     muss laufen), danach den Node Manager neu starten (Rest von 1b).

  echo "Domain-Name fuer cd() in WLST: $DOMAIN_NAME"
  # Erwartet: reportRpgpi

  $WLST

  # --- in WLST eingeben ---

      connect('weblogic', '<WLS_ADMIN_PASSWORD>', 't3://localhost:7001')

      edit()

      startEdit()

      cd('/SecurityConfiguration/<DOMAIN_NAME>')

      cmo.setNodeManagerPassword('<WLS_ADMIN_PASSWORD>')

SCHRITT 2: Umgebungsdatei anlegen  (als oracle)
================================================================================

  systemd liest KEIN ~/.bash_profile - alle Werte stehen deshalb in einer
  eigenen Datei, die beide Skripte einlesen. Sie enthaelt auch zwei kleine
  Warte-Funktionen, die beide Skripte nutzen.

  Die Werte in der Datei sind fest eingetragen ('EOF' = nichts wird
  ersetzt). Weicht die Umgebung von SCHRITT 0 ab: nach dem Anlegen mit vi
  anpassen und mit 2.1 pruefen.

  mkdir -p $SCRIPTS

  cat > $SCRIPTS/report_env.sh << 'EOF'
#!/bin/bash
# Umgebung fuer start_all.sh / stop_all.sh (Autostart_linux_middleware.txt)

export ORACLE_HOME=/u01/oracle/fmw
export DOMAIN_HOME=/u01/user_projects/domains/reportRpgpi
export WLS_MANAGED_SERVER=WLS_REPORTS
export WLS_ADMIN_URL=t3://localhost:7001
export REPORTS_TOOLS_INSTANCE=reptools1
export REPORTS_SERVER_NAME=repServer01
export LOG_DIR=$DOMAIN_HOME/logs

# Obergrenzen in Sekunden (keine festen Pausen - es wird nur so lange
# gewartet wie noetig)
WAIT_NODEMANAGER=120
WAIT_ADMIN=600
WAIT_MANAGED=600
WAIT_STOP=300

# wait_running <logdatei> <sekunden> <name>
# Wartet, bis WebLogic "Server state changed to RUNNING" ins Log schreibt.
wait_running() {
    local log="$1" max="$2" name="$3" t=0
    until grep -q "Server state changed to RUNNING" "$log" 2>/dev/null; do
        sleep 5; t=$((t + 5))
        if [ "$t" -ge "$max" ]; then
            echo "FEHLER: $name nach ${max}s nicht RUNNING - siehe $log"
            return 1
        fi
    done
    echo "$name laeuft (RUNNING nach ${t}s)"
}

# wait_stopped <prozessmuster> <sekunden> <name>
# Wartet, bis kein Prozess mit diesem Muster mehr laeuft.
wait_stopped() {
    local pattern="$1" max="$2" name="$3" t=0
    while pgrep -f "$pattern" > /dev/null; do
        sleep 5; t=$((t + 5))
        if [ "$t" -ge "$max" ]; then
            echo "WARNUNG: $name laeuft nach ${max}s immer noch"
            return 1
        fi
    done
    echo "$name gestoppt"
}
EOF

  ----------------------------------------------------------------------------
  2.1 Kontrolle: passen die Werte zu SCHRITT 0?
  ----------------------------------------------------------------------------
  grep -n '^export' $SCRIPTS/report_env.sh
  # Erwartet: dieselben Werte wie "echo" in 0.4 (ORACLE_HOME, DOMAIN_HOME,
  # WLS_MANAGED_SERVER, WLS_ADMIN_URL, REPORTS_TOOLS_INSTANCE,
  # REPORTS_SERVER_NAME, LOG_DIR).

SCHRITT 3: Start-Skript anlegen  (als oracle)
================================================================================

  Der Node-Manager-Port 5556 ist im Skript fest eingetragen - bei einem
  anderen WLS_NODEMANAGER_PORT danach mit vi anpassen.

  cat > $SCRIPTS/start_all.sh << 'EOF'
#!/bin/bash
# Startet Node Manager, AdminServer, Managed Server und die
# Reports-Komponenten. Bereits laufende Teile werden uebersprungen.
source /u01/oracle/scripts/report_env.sh
mkdir -p "$LOG_DIR"
cd "$DOMAIN_HOME" || exit 1

echo "=== 1/4 Node Manager ==="
if pgrep -f "weblogic.NodeManager" > /dev/null; then
    echo "laeuft bereits"
else
    nohup "$DOMAIN_HOME/bin/startNodeManager.sh" > "$LOG_DIR/NodeManager.out" 2>&1 &
    t=0
    until ss -tln | grep -q ":5556 "; do
        sleep 5; t=$((t + 5))
        if [ "$t" -ge "$WAIT_NODEMANAGER" ]; then
            echo "WARNUNG: Node-Manager-Port 5556 nach ${t}s nicht offen"
            break
        fi
    done
fi

echo "=== 2/4 AdminServer ==="
if pgrep -f "weblogic.Name=AdminServer" > /dev/null; then
    echo "laeuft bereits"
else
    # libOVD-Sperre des Reports-Servers entfernen - sonst findet der EM
    # unter "Principal hinzufuegen" keine Benutzer (Reports_security.txt)
    mv -f "$DOMAIN_HOME/config/fmwconfig/ovd/default/ovd.lok" \
          "$DOMAIN_HOME/config/fmwconfig/ovd/default/ovd.lok.stale" 2>/dev/null
    nohup "$DOMAIN_HOME/bin/startWebLogic.sh" > "$LOG_DIR/AdminServer.out" 2>&1 &
    # Ohne AdminServer kann der Managed Server nicht starten - hier abbrechen
    wait_running "$LOG_DIR/AdminServer.out" "$WAIT_ADMIN" "AdminServer" || exit 1
fi

echo "=== 3/4 Managed Server ($WLS_MANAGED_SERVER) ==="
if pgrep -f "weblogic.Name=$WLS_MANAGED_SERVER" > /dev/null; then
    echo "laeuft bereits"
else
    nohup "$DOMAIN_HOME/bin/startManagedWebLogic.sh" "$WLS_MANAGED_SERVER" "$WLS_ADMIN_URL" \
        > "$LOG_DIR/ManagedServer.out" 2>&1 &
    # Nur warnen, nicht abbrechen: ein langsamer Start soll den AdminServer
    # nicht wieder mit herunterreissen
    wait_running "$LOG_DIR/ManagedServer.out" "$WAIT_MANAGED" "$WLS_MANAGED_SERVER"
fi

echo "=== 4/4 Reports-Komponenten ==="
"$DOMAIN_HOME/bin/startComponent.sh" "$REPORTS_TOOLS_INSTANCE"
"$DOMAIN_HOME/bin/startComponent.sh" "$REPORTS_SERVER_NAME"

echo "Start abgeschlossen. Logs: $LOG_DIR"
exit 0
EOF

  grep -n '5556' $SCRIPTS/start_all.sh
  # Erwartet: zwei Zeilen mit 5556 (= WLS_NODEMANAGER_PORT aus SCHRITT 0)

SCHRITT 4: Stop-Skript anlegen  (als oracle)
================================================================================

  Die Server werden OHNE Benutzer/Passwort gestoppt: die Oracle-Skripte
  stopManagedWebLogic.sh / stopWebLogic.sh nutzen dann die boot.properties
  des jeweiligen Servers - deshalb wechselt das Skript vorher ins
  DOMAIN_HOME. Unbedingt in Schritt 5 von Hand testen!

  cat > $SCRIPTS/stop_all.sh << 'EOF'
#!/bin/bash
# Stoppt Reports-Komponenten, Managed Server, AdminServer und Node Manager.
source /u01/oracle/scripts/report_env.sh
cd "$DOMAIN_HOME" || exit 1

echo "=== 1/4 Reports-Komponenten ==="
"$DOMAIN_HOME/bin/stopComponent.sh" "$REPORTS_SERVER_NAME"
"$DOMAIN_HOME/bin/stopComponent.sh" "$REPORTS_TOOLS_INSTANCE"

echo "=== 2/4 Managed Server ($WLS_MANAGED_SERVER) ==="
if pgrep -f "weblogic.Name=$WLS_MANAGED_SERVER" > /dev/null; then
    "$DOMAIN_HOME/bin/stopManagedWebLogic.sh" "$WLS_MANAGED_SERVER" "$WLS_ADMIN_URL"
    wait_stopped "weblogic.Name=$WLS_MANAGED_SERVER" "$WAIT_STOP" "$WLS_MANAGED_SERVER"
fi

echo "=== 3/4 AdminServer ==="
if pgrep -f "weblogic.Name=AdminServer" > /dev/null; then
    "$DOMAIN_HOME/bin/stopWebLogic.sh"
    wait_stopped "weblogic.Name=AdminServer" "$WAIT_STOP" "AdminServer"
fi

echo "=== 4/4 Node Manager ==="
if pgrep -f "weblogic.NodeManager" > /dev/null; then
    "$DOMAIN_HOME/bin/stopNodeManager.sh"
    wait_stopped "weblogic.NodeManager" 60 "Node Manager"
fi

echo "Stop abgeschlossen."
exit 0
EOF

  chmod 755 $SCRIPTS/*.sh

  ls -l $SCRIPTS

SCHRITT 6: systemd-Dienst anlegen  (als root, vorher SCHRITT 0.5)
================================================================================

  WICHTIG: Fuer systemd-Dienste gelten die oracle-Limits aus
  /etc/security/limits.d/ NICHT (die greifen nur bei einer Anmeldung).
  Ohne die Limit*-Zeilen liefe WebLogic mit nur 1024 offenen Dateien.
  Werte wie in OS_Kochbuch_de.txt (oracle-Limits) - wurden dort andere
  Werte gesetzt, hier dieselben eintragen.

  echo "Unit: /etc/systemd/system/$SERVICE.service"
  # Erwartet: /etc/systemd/system/reportrpgpi.service. LEER? -> 0.5

  cat > /etc/systemd/system/$SERVICE.service << 'EOF'
[Unit]
Description=Oracle Reports Middleware (WebLogic Domain reportRpgpi)
Wants=network-online.target
After=network-online.target

[Service]
Type=oneshot
RemainAfterExit=yes
User=oracle
Group=oinstall
LimitNOFILE=65536
LimitNPROC=16384
LimitSTACK=10485760
ExecStart=/u01/oracle/scripts/start_all.sh
ExecStop=/u01/oracle/scripts/stop_all.sh
TimeoutStartSec=1500
TimeoutStopSec=900

[Install]
WantedBy=multi-user.target
EOF

  systemctl daemon-reload

                                Hand (WLS_Report_start_stop_kochbuch.txt)
    Unit ganz entfernen         systemctl stop reportrpgpi, disable, dann
                                /etc/systemd/system/reportrpgpi.service
                                loeschen, systemctl daemon-reload
    Skripte                     $SCRIPTS (/u01/oracle/scripts) - eigene
                                Dateien, Oracle-Dateien werden nicht
                                geaendert
    Node-Manager-Zugang (1b)    nur per WLST wie in 1b wieder aendern


================================================================================
BEKANNTE PROBLEME UND LOESUNGEN
================================================================================

  Problem: stop_all.sh bricht beim Managed Server oder AdminServer mit "No
           valid username/password or userConfigFile/userKeyFile provided" ab
  Ursache: boot.properties fehlt fuer diesen Server, oder stopWebLogic.sh/
           stopManagedWebLogic.sh wurde nicht aus dem DOMAIN_HOME aufgerufen
  Loesung: boot.properties pruefen (siehe SCHRITT 0.4, ggf. nach
           Reports_kochbuch_de.txt Schritt 4/6 neu anlegen; nach dem
           naechsten Serverstart steht dort "{AES256}..."). stop_all.sh wechselt
           selbst ins DOMAIN_HOME - daran nichts aendern.

  Problem: startComponent.sh/stopComponent.sh fragt nach einem Passwort,
           oder der Dienst haengt bei den Reports-Komponenten
  Ursache: Schritt 1 (storeUserConfig) nicht ausgefuehrt, oder als anderer
           Benutzer als oracle - die gespeicherten Zugangsdaten liegen als
           ~/oracle-WebLogicConfig.properties + ~/oracle-WebLogicKey.properties
           im Home-Verzeichnis des Benutzers, der storeUserConfig ausgefuehrt hat
  Loesung: Schritt 1 als oracle wiederholen

  Problem: startComponent.sh meldet "Connection refused. Could not connect
           to NodeManager ... localhost/127.0.0.1:5556"
  Ursache: der Node Manager laeuft nicht (das Passwort spielt hier noch
           keine Rolle)
  Loesung: Node Manager starten (Schritt 1a), dann erneut versuchen

  Problem: "Please enter Node Manager password" - aber kein bekanntes
           Passwort passt
  Ursache: die Domain hat zufaellige Node-Manager-Zugangsdaten
           (<node-manager-username> in config.xml ist eine zufaellige
           Zeichenkette)
  Loesung: Schritt 1b - Node-Manager-Zugangsdaten per WLST auf den
           WebLogic-Administrator setzen, Node Manager neu starten

  Problem: "systemctl start" endet mit "failed", AdminServer laeuft nicht
  Ursache: AdminServer wurde innerhalb von WAIT_ADMIN (600 s) nicht RUNNING
  Loesung: $DOMAIN_HOME/logs/AdminServer.out pruefen; auf einer langsamen
           Maschine WAIT_ADMIN in report_env.sh erhoehen (und
           TimeoutStartSec in der Unit entsprechend)

  Problem: Managed Server "nicht RUNNING", der Dienst ist aber "active (exited)"
  Ursache: Gewollt - ein langsamer Managed Server soll den bereits
           laufenden AdminServer nicht mit beenden
  Loesung: $DOMAIN_HOME/logs/ManagedServer.out pruefen, ggf. spaeter
           "systemctl restart reportrpgpi"

  Problem: Nach dem Neustart "Too many open files" in den Logs
  Ursache: Limit*-Zeilen in der Unit fehlen oder sind zu klein
  Loesung: Schritt 6 pruefen, danach "systemctl daemon-reload" und
           "systemctl restart reportrpgpi"
