SCHRITT 1: Hostname, DNS und Zeitsynchronisation  (als root)
================================================================================

  ----------------------------------------------------------------------------
  1.1 Hostname pruefen
  ----------------------------------------------------------------------------
  # Kurzer und vollqualifizierter Hostname muessen zusammenpassen und
  # DNS-aufloesbar sein - WebLogic/Forms&Reports reagieren empfindlich auf
  # falsch konfigurierte Hostnamen (T3-Verbindungsprobleme, falsche
  # Redirect-URLs).

  hostname

  hostname -f
  # Erwartet: der FQDN, z.B. wls01.company.local (= $WLS_SERVER_FQDN)

  hostnamectl status

  # /etc/hosts PRUEFEN: FQDN muss VOR dem Kurznamen stehen, sonst liefert
  # "hostname -f" den Kurznamen zurueck.
  #   Falsch:  192.168.1.10  wls01  wls01.company.local
  #   Richtig: 192.168.1.10  wls01.company.local  wls01

  grep -i "$(hostname)" /etc/hosts

  ----------------------------------------------------------------------------
  1.2 DNS pruefen
  ----------------------------------------------------------------------------
  FQDN=$(hostname -f)

  echo "FQDN=$FQDN"

  # Forward-DNS pruefen (muss die eigene IP liefern, nicht leer/loopback)

  getent hosts "$FQDN"

  dig +short "$FQDN" A

  # Reverse-DNS (PTR) pruefen - nur Warnung, kein Hard-Fail, wenn nicht
  # gesetzt, aber fuer sauberen Betrieb empfohlen

  MYIP=$(hostname -I | awk '{print $1}')

  echo "MYIP=$MYIP"

  dig -x "$MYIP" +short

  # Resolver-Konfiguration pruefen: nameserver + search/domain muessen
  # gesetzt sein

  cat /etc/resolv.conf

  grep '^hosts:' /etc/nsswitch.conf
  # Erwartet: "hosts: files dns" (files VOR dns)

  ----------------------------------------------------------------------------
  1.3 IPv6 deaktivieren
  ----------------------------------------------------------------------------
  # WebLogic/Node Manager Listen-Adressen sind sonst instabil zwischen
  # 127.0.0.1 und ::1.

  sysctl -n net.ipv6.conf.all.disable_ipv6

  cat >> /etc/sysctl.d/99-oracle-fmw.conf << 'EOF'
net.ipv6.conf.all.disable_ipv6     = 1
net.ipv6.conf.default.disable_ipv6 = 1
EOF

  sysctl --system

  # WICHTIG: "default" gilt nur fuer Netzwerkkarten, die DANACH angelegt
  # werden - eine schon vorhandene Karte behaelt ihren eigenen Wert, und der
  # NetworkManager schaltet IPv6 pro Verbindung wieder ein. Beim Kunden so
  # aufgetreten (2026-10): all=1, default=1, aber ens33=0 mit fe80::-Adresse
  # -> die Java-Prozesse lauschten ueber IPv6. Deshalb JEDE Karte pruefen:

  sysctl -a 2>/dev/null | grep -E "net.ipv6.conf.*.disable_ipv6"
  # Erwartet: ueberall "= 1". Steht bei einer Karte (z.B. ens33) "= 0":
  #   sysctl -w net.ipv6.conf.ens33.disable_ipv6=1          # sofort
  #   nmcli -g GENERAL.CONNECTION device show ens33         # Verbindungsname
  #   nmcli connection modify "<Verbindung>" ipv6.method disabled   # dauerhaft
  # (nmcli wirkt bei der naechsten Aktivierung bzw. beim Reboot in SCHRITT 2.)

  ip -6 addr show
  # Erwartet nach dem Reboot: keine Ausgabe (keine IPv6-Adresse mehr)

  ----------------------------------------------------------------------------
  1.4 localhost muss auf 127.0.0.1 zeigen
  ----------------------------------------------------------------------------
  # localhost MUSS auf IPv4 (127.0.0.1) aufloesen, nicht auf ::1 - sonst
  # binden manche JVM-Prozesse auf die falsche Adresse.

  getent -s files hosts localhost
  # Erwartet: 127.0.0.1  localhost ...
  # Falls hier "::1" statt "127.0.0.1" erscheint, in /etc/hosts die Zeile
  # fuer ::1 korrigieren (vorher: cp -p /etc/hosts /etc/hosts.bak):
  #   Vorher (falsch):
  #     ::1   localhost localhost.localdomain localhost6 localhost6.localdomain6
  #   Nachher (richtig):
  #     ::1   localhost6 localhost6.localdomain6

  ----------------------------------------------------------------------------
  1.5 Zeitsynchronisation (chrony)
  ----------------------------------------------------------------------------
  # WebLogic/OPSS-Zertifikatspruefungen reagieren empfindlich auf
  # Zeitabweichungen zwischen Knoten.

  dnf install -y chrony

  systemctl enable chronyd

  cp -p /etc/chrony.conf /etc/chrony.conf.bak

  # Deutsche NTP-Pools eintragen

  cat >> /etc/chrony.conf << 'EOF'
pool 0.de.pool.ntp.org iburst
pool 1.de.pool.ntp.org iburst
EOF

  systemctl restart chronyd

  # Kontrolle: Synchronisation aktiv?

  chronyc -n sources -v

  chronyc -n tracking

  timedatectl show --property=NTPSynchronized
  # Erwartet: NTPSynchronized=yes

  # Hardware-Uhr einmalig nach Sync schreiben

  hwclock -w

  ----------------------------------------------------------------------------

fs.file-max           = 6815744

net.core.rmem_default = 262144
net.core.rmem_max     = 4194304
net.core.wmem_default = 262144
net.core.wmem_max     = 4194304

  sysctl -n net.ipv6.conf.all.disable_ipv6

  # Erwartet: 1

  # Core-Dump-Verzeichnis pruefen

  mkdir -p /var/tmp/core/

  chmod 777 /var/tmp/core/

  # Notiz (Autor, offen): aus sysctl.conf default rausnehmen??

  ----------------------------------------------------------------------------
  2.4 Konflikt-Check mit anderen sysctl-Dateien
  ----------------------------------------------------------------------------
  # WICHTIG - Konflikt-Check: Da die Datenbank bei diesem Kunden EXTERN
  # betrieben wird (kein lokales DB-Preinstall-RPM auf diesem Host), darf
  # hier KEIN anderes Paket (z.B. oracle-database-preinstall-*) bereits
  # andere shmmax/shmall-Werte gesetzt haben - diese wuerden /etc/sysctl.conf
  # als zuletzt geladene Datei die obigen Werte sonst stillschweigend
  # ueberschreiben. Pruefen:

  grep -rE 'shmmax|shmall' /etc/sysctl.d/*.conf /etc/sysctl.conf 2>/dev/null
  # Erwartet: nur die zwei Zeilen aus 99-oracle-fmw.conf
  # Falls ein Konflikt gefunden wird (z.B. durch ein DB-Preinstall-Paket),
  # die abweichende Zeile sichern und auskommentieren:
  #   cp /etc/sysctl.conf /etc/sysctl.conf.bak_<JJJJMMTT>
  #   sed -i 's/^kernel\.shmmax[[:space:]]*=/# [oracle-fmw] kernel.shmmax =/' /etc/sysctl.conf
  #   sysctl --system

  ----------------------------------------------------------------------------
  2.5 Transparent HugePages deaktivieren  (wirkt erst nach dem Neustart)
  ----------------------------------------------------------------------------
  # Kann JVM-Pausen/GC-Spitzen verursachen.

  cat /sys/kernel/mm/transparent_hugepage/enabled

  # Notiz (Autor): gpi Beispiel

  grubby --update-kernel=ALL --args="transparent_hugepage=never"

  ----------------------------------------------------------------------------
  2.6 /dev/shm pruefen
  ----------------------------------------------------------------------------
  # /dev/shm (tmpfs) muss mind. 25% des RAM gross sein (min. 2 GB) und
  # darf NICHT "noexec" gesetzt haben (JVM braucht Exec-Rechte dort).

  df -h /dev/shm

  grep /dev/shm /etc/fstab

  # Beispiel-Eintrag in /etc/fstab (N = Groesse in MB, z.B. 8192 fuer 8 GB):
  #   tmpfs /dev/shm tmpfs rw,exec,size=8192M 0 0
  # Notiz (Autor): GPI

  systemctl daemon-reload

  mount -o remount /dev/shm

  df -h /dev/shm
  # Erwartet: die neue Groesse

  ----------------------------------------------------------------------------
  2.7 Swap-Speicher
  ----------------------------------------------------------------------------

  free -h

  mkdir -p /u01/oracle

  # /u01/oracle entsteht sonst erst in SCHRITT 5.5 (Besitzer setzt 5.5)

  fallocate -l 2G /u01/oracle/swapfile

  chmod 600 /u01/oracle/swapfile

  mkswap /u01/oracle/swapfile

  swapon /u01/oracle/swapfile

  cp -p /etc/fstab /etc/fstab.bak

  echo "/u01/oracle/swapfile none swap sw 0 0" >> /etc/fstab

  free -h
  # Erwartet: Swap um 2 GB groesser

  # Core-Dump-Verzeichnis anlegen (777, da sowohl oracle als auch native
  # Prozesse dorthin schreiben muessen)

  mkdir -p /var/tmp/core

  chmod 777 /var/tmp/core

  ----------------------------------------------------------------------------
  2.8 Firewall: Ports fuer Nginx und Reports

  # (nur ueber den Reverse-Proxy erreichbar).

  firewall-cmd --state
  # "running"     -> die Befehle unten ausfuehren
  # "not running" -> die Befehle hier ueberspringen und die Firewall erst
  #                  in SCHRITT 9 mit Sicherheitsnetz einschalten (dort
  #                  auch SSH-Haertung)

  firewall-cmd --permanent --add-port=80/tcp

  firewall-cmd --permanent --add-port=443/tcp

  # Reports-Server-Erkennung (Multicast 228.5.6.7, UDP): der Reports Server
  # schickt beim Start ein Multicast-Paket und muss Pakete EMPFANGEN koennen,
  # sonst beendet er sich mit "REP-50600 Broadcasting is disabled" und der
  # Node Manager startet ihn in einer Schleife neu (beim Kunden so
  # aufgetreten, 2026-10). Port = REPORTS_BROADCAST_PORT aus
  # Reports_kochbuch_de.txt 9.2 (Beispiel 14027, je Umgebung im Netz
  # eindeutig, Bereich 14021-14030):

  firewall-cmd --permanent --add-port=$REPORTS_BROADCAST_PORT/udp

  firewall-cmd --reload

  firewall-cmd --list-ports
  # Erwartet: 80/tcp 443/tcp 14027/udp - 7001/9002/5556 duerfen HIER NICHT
  # auftauchen

  cat /sys/kernel/mm/transparent_hugepage/enabled
  # Erwartet: always madvise [never]

SCHRITT 9: Netzwerk absichern - Firewall und SSH  (als root, mit Sicherheitsnetz)
================================================================================

  # Warum: Ohne Firewall sind alle Prozesse aus dem Netz erreichbar, die auf
  # allen Interfaces lauschen - nicht nur Nginx. Auf dem Testsystem waren
  # das ~50 vorgestartete Forms-Prozesse (frmweb), der Reports Server, die
  # Reports-Engines und Coherence - alles am Nginx vorbei. Ziel:
  #
  #     Netz  -> nur 22 (ssh), 80 + 443 (Nginx), 14027/udp (Reports)
  #              alles andere (7001, 9001, 9002, 5556, frmweb, Engines) zu
  #     ausgehend: unveraendert (MOS-Downloads, NTP, ...)
  #     lo:        immer erlaubt (WebLogic -> DB auf demselben Host)
  #
  # WICHTIG vor dem Start:
  #   - eine KONSOLEN-Sitzung (VMware / vSphere / iLO) als root/admin offen
  #     halten - die bleibt erhalten, egal was mit ssh passiert
  #   - die laufende ssh-Sitzung NICHT schliessen, bis ein NEUER Login klappt
  #   - die Sicherheitsnetze unten (systemd-run) nehmen jede Aenderung nach
  #     15 Minuten automatisch zurueck, wenn sie nicht bestaetigt wird

  ----------------------------------------------------------------------------
  9.1 Firewall
  ----------------------------------------------------------------------------
  systemctl is-active firewalld
  # "inactive" -> weiter mit dem naechsten Befehl
  # "active"   -> direkt 9.1b

  firewall-offline-cmd --get-default-zone
  # Erwartet: meist "public"

  # ssh MUSS in der Zone stehen, sonst sperrt man sich aus:

  firewall-offline-cmd --zone=public --query-service=ssh
  # Erwartet: yes
  # "no" -> STOP, zuerst ssh in die Zone aufnehmen

  # Sicherheitsnetz: stoppt die Firewall in 15 min wieder von selbst

  systemd-run --on-active=15min --unit=ihw-fw-rollback systemctl stop firewalld

  systemctl start firewalld

  ----------------------------------------------------------------------------
  9.1b Freigaben  (dauerhaft + sofort wirksam)
  ----------------------------------------------------------------------------
  firewall-cmd --permanent --add-service=ssh --add-service=http --add-service=https

  firewall-cmd --permanent --add-port=$REPORTS_BROADCAST_PORT/udp
  # REPORTS_BROADCAST_PORT (Beispiel 14027)

  # cockpit (Web-Konsole, Port 9090) wird auf einem FMW-Server nicht gebraucht:

  firewall-cmd --permanent --remove-service=cockpit

  firewall-cmd --reload

  firewall-cmd --list-all
  # Erwartet: services nur ssh/http/https (+ dhcpv6-client),
  #           ports 14027/udp

  # JETZT TESTEN (vom Arbeitsplatz aus):
  #   - neuer ssh-Login (zweites Fenster / MobaXterm / PuTTY)
  #   - Browser: https://<server>/reports/rwservlet/getserverinfo  (Login-Seite)
  #   - Windows PowerShell:
  #       Test-NetConnection <server> -Port 443    -> TcpTestSucceeded True
  #       Test-NetConnection <server> -Port 9002   -> TcpTestSucceeded False
  # Alles ok -> dauerhaft machen und Sicherheitsnetz entfernen.
  # Etwas geht NICHT -> nichts tun, nach 15 min ist die Firewall wieder aus.

  systemctl enable firewalld

  systemctl stop ihw-fw-rollback.timer

  ----------------------------------------------------------------------------
  9.2 SSH absichern (sshd)
  ----------------------------------------------------------------------------
  # Nur die Benutzer, die wirklich per ssh auf den Server muessen (hier:
  # admin + oracle), kein root-Login, kein X11 (auf einem Server wird alles
  # per Skript gemacht), 3 Passwortversuche. Bei Anmeldung ueber AD/LDAP-
  # Gruppen statt AllowUsers die Zeile "AllowGroups <gruppe>" verwenden -
  # vorher mit der eigenen IT abstimmen.
  #
  # Unter OL9 gilt pro Einstellung der ERSTE Wert. Die Datei 10-... wird vor
  # der Red-Hat-Datei 50-redhat.conf gelesen; der Match-Block steht in einer
  # eigenen Datei 99-..., weil er bis zum Dateiende gilt.

  cat > /etc/ssh/sshd_config.d/10-ihw-hardening.conf << 'CNF'
# Server-Haertung - siehe OS_Kochbuch_de.txt Schritt 9.2
PermitRootLogin no
MaxAuthTries 3
X11Forwarding no
AllowUsers admin oracle
PasswordAuthentication no
CNF

  # Passwort-Login nur fuer diese Benutzer (Notzugang ohne Schluessel);
  # alle anderen erlaubten Benutzer brauchen ~/.ssh/authorized_keys

  cat > /etc/ssh/sshd_config.d/99-ihw-match.conf << 'CNF'
Match User admin,oracle
    PasswordAuthentication yes
CNF

  chmod 600 /etc/ssh/sshd_config.d/10-ihw-hardening.conf \
            /etc/ssh/sshd_config.d/99-ihw-match.conf

  # Syntax pruefen - bei Fehler NICHT weitermachen, Dateien wieder loeschen

  sshd -t && echo "sshd config OK"
  # Erwartet: sshd config OK
  # Andere Ausgabe -> STOP, die beiden Dateien loeschen (RUECKWEG)

  # Sicherheitsnetz: entfernt die beiden Dateien in 15 min wieder
  # (sh -c, weil systemd-run nur EINEN Befehl startet)

  systemd-run --on-active=15min --unit=ihw-ssh-rollback /bin/sh -c \
      "rm -f /etc/ssh/sshd_config.d/10-ihw-hardening.conf /etc/ssh/sshd_config.d/99-ihw-match.conf; systemctl reload sshd"

  # reload (nicht restart): bestehende Sitzungen bleiben bestehen

  systemctl reload sshd

  # Kontrolle der wirksamen Werte je Benutzer:

  sshd -T -C user=admin,host=x,addr=10.0.0.1 | awk '$1 ~ /^(passwordauthentication|permitrootlogin|x11forwarding)$/ {print $1 "=" $2}'
  # Erwartet: passwordauthentication=yes, x11forwarding=no

  sshd -T -C user=oracle,host=x,addr=10.0.0.1 | awk '$1 ~ /^(passwordauthentication|permitrootlogin|x11forwarding)$/ {print $1 "=" $2}'
  # Erwartet: passwordauthentication=yes, x11forwarding=no

  sshd -T -C user=root,host=x,addr=10.0.0.1 | awk '$1 ~ /^(passwordauthentication|permitrootlogin|x11forwarding)$/ {print $1 "=" $2}'
  # Erwartet: passwordauthentication=no, permitrootlogin=no, x11forwarding=no

  # JETZT TESTEN: neuer ssh-Login als admin UND als oracle (zweites Fenster),
  # root muss abgewiesen werden. Alles ok -> Sicherheitsnetz entfernen:

  systemctl stop ihw-ssh-rollback.timer

  # NICHT aendern: AllowTcpForwarding (VS Code / MobaXterm-Tunnel brauchen es),
  # LoginGraceTime 0 in /etc/ssh/sshd_config (Oracle-Schutz gegen CVE-2024-6387).

BEKANNTE PROBLEME UND LOESUNGEN
================================================================================

  Problem: "hostname -f" liefert nur den Kurznamen
  Ursache: /etc/hosts hat den Kurznamen VOR dem FQDN stehen
  Loesung: Reihenfolge in /etc/hosts korrigieren (FQDN zuerst), Schritt 1.1

  Problem: sysctl-Werte wirken nicht / werden nach Neustart wieder anders
  Ursache: Ein anderes *.conf in /etc/sysctl.d/ oder /etc/sysctl.conf
           ueberschreibt 99-oracle-fmw.conf (laedt alphabetisch, zuletzt
           gewinnt - /etc/sysctl.conf laedt immer zuletzt)
  Loesung: Schritt 2.4:
             grep -rE 'shmmax|shmall' /etc/sysctl.d/*.conf /etc/sysctl.conf

           Konfliktzeile sichern und auskommentieren, sysctl --system

  Problem: WebLogic-Start dauert sehr lange (mehrere Minuten bis zur
           ersten Logzeile)
  Ursache: SecureRandom liest aus /dev/random (blockierend) statt
           /dev/urandom
  Loesung: Schritt 4.5 fuer BEIDE JDKs durchfuehren (Standalone-JDK hier
           UND die FMW-eigene JDK nach der Installation, siehe
           FMW_Kochbuch_de.txt)

  Problem: dnf meldet bei Schritt 3 "No match for argument" / "Unable to
           find a match" fuer motif, libnsl2, compat-openssl11, ksh u.a.

  Ursache: das AppStream-Repository ist nicht aktiv (beim Kunden so
           aufgetreten) - diese Pakete gibt es nur dort, nicht in BaseOS
  Loesung: Schritt 3.0: "dnf repolist" pruefen, AppStream mit
           "dnf config-manager --set-enabled ol9_appstream" bzw. im
           Repo-Spiegel/ULN freischalten, Schritt 3 wiederholen.
           Ohne jeden Repo-Zugang: RPM auf einer anderen OL9-Maschine mit
           "dnf download <paket>" holen (oder von yum.oracle.com, Bereich
           "Oracle Linux 9 AppStream (x86_64)") und beim Kunden mit
           "dnf install -y ./<paket>.rpm" installieren

  Problem: Installer bricht mit "motif not found" ab
  Ursache: Paket motif/motif-devel fehlt (wird vom Installer per exaktem
           Namen gesucht, keine Alternative akzeptiert)
  Loesung: dnf install -y motif motif-devel (Schritt 3 erneut ausfuehren)

  Problem: nginx -t meldet "cannot load certificate" beim ersten Test
  Ursache: Zertifikat wird erst im naechsten Kochbuch (FMW_Kochbuch_de.txt)
           abgelegt - an dieser Stelle normal und zu erwarten
  Loesung: Weiter mit SSL_Kochbuch_de.txt + FMW_Kochbuch_de.txt

  Problem: Nach dem Einschalten der Firewall kein ssh-Login mehr moeglich
  Ursache: Service ssh nicht in der Zone (eigene Zone ohne ssh) oder
           Login-Benutzer nicht in AllowUsers
  Loesung: Ueber die Konsole (VM/iLO) anmelden: systemctl stop firewalld
           bzw. die Dateien /etc/ssh/sshd_config.d/10-ihw-hardening.conf und
           99-ihw-match.conf loeschen, systemctl reload sshd. Mit den
           Sicherheitsnetzen aus Schritt 9 passiert das nach 15 min von selbst.

  Problem: Reports Server startet nach dem Einschalten der Firewall immer
           wieder neu (REP-50600 Broadcasting is disabled)
  Ursache: 14027/udp (REPORTS_BROADCAST_PORT) fehlt in der Firewall
  Loesung: Schritt 9.1b:
             firewall-cmd --permanent --add-port=14027/udp
             firewall-cmd --reload
