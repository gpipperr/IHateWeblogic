================================================================================

  CVE-2026-91403 trifft vor allem den Client (Forms-Client = JSSE-TLS-
  Client). Patch 40186686 = JRE 8u511 Alert-Build (1.8.0_511-b26 oder neuer
  - eMudhra-Alert CVE-2026-114820: neuesten Build nehmen), in der Bitness,
  die die Clients heute nutzen (heute 32 Bit -> Windows x86; WebUtil-/
  JACOB-DLLs muessen zur Bitness passen).
  Vorher auf wenigen PCs testen: TLS 1.2 am Webserver, Signatur der eigenen
  Jars (kein SHA-1, Schluessellaenge, Zeitstempel), Vertrauen der Jar-
  Signatur nach dem JRE-Tausch (cacerts wird ersetzt).
  Nachweis am Client: java -version -> 1.8.0_511-b26 oder neuer.
  eMudhra-Pruefung wie in 4.8.

  ----------------------------------------------------------------------------
  11.1 Standalone-Client (FSAL, frmsal.jar): lokale Kopie neu holen
  ----------------------------------------------------------------------------
  Die LOKALE frmsal.jar MUSS nach der Forms-QPR neu vom Server geholt
  werden. frmsal.jar enthaelt selbst Klassen aus oracle.forms.engine,
  frmall.jar (Server) ebenfalls. Die QPR bringt ein neu signiertes
  frmall.jar; eine alte lokale frmsal.jar ist mit einem aelteren Oracle-
  Zertifikat signiert -> Java lehnt das Paket ab:
    java.lang.SecurityException: class "oracle.forms.engine.Main"'s
    signer information does not match signer information of other
    classes in the same package
  Kunde 2026-11-02 bestaetigt: Ursache war das eigene Startprogramm, das
  frmsal.jar nur laedt, wenn die lokale Datei fehlt - nach dem Patch blieb
  die alte liegen. Lokale Kopie geloescht, neu geladen -> laeuft, KEIN
  Neusignieren noetig. fsalcheck=true in formsweb.cfg hat die alte Kopie
  NICHT abgefangen.

  Abhilfe am Client: lokale frmsal*.jar loeschen (wird neu geladen), bei
  Bedarf zusaetzlich den FSAL-Cache unter
  %USERPROFILE%\...\frmsal\<host>\<version>\ leeren. Nach JEDER Forms-QPR
  auf allen Clients noetig, solange das Startprogramm so arbeitet.
  Dauerhaft: das Startskript laedt frmsal.jar bei jeder Aenderung neu,
  z.B. mit "curl -z <lokale Datei> -o <lokale Datei> <url>" oder mit dem
  Patch-Stand im Dateinamen.

  # Pruefen - Server und Client muessen DASSELBE Zertifikat zeigen:

  keytool -printcert -jarfile $ORACLE_HOME/forms/java/frmsal.jar | grep -E 'Owner|Valid|SHA256:'

  keytool -printcert -jarfile $ORACLE_HOME/forms/java/frmall.jar | grep -E 'Owner|Valid|SHA256:'

  # (am Client dasselbe mit der lokalen frmsal*.jar)
