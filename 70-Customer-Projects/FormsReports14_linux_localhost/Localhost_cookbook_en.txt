                 They were not run by hand from this cookbook.
  Important  : - Maintenance window: the whole domain is restarted (STEP 6),
                 Forms and Reports are away for some minutes.
               - Ask for a VM snapshot before you start.
               - Afterwards the ports 7001 / 9001 / 9002 are no longer

               - Sections marked "Forms only - skip if Reports only" are
                 left out on a domain without WLS_FORMS.
               - No step changes the database, the RCU prefix or a

TARGET STATE
------------

  What                              today (typical)        target     step
  --------------------------------  ---------------------  ---------  -------
  AdminServer      (port 7001)      all interfaces         localhost  3
  WLS_FORMS        (port 9001)      all interfaces         localhost  3 (F)
  WLS_REPORTS      (port 9002)      all interfaces         localhost  3
  SSL listen ports of the managed   on (demo certificate)  off        3
  servers (9501 / 9512)
  Coherence member traffic          host IP (automatic)    127.0.0.1  3
  Node Manager     (port 5556)      127.0.0.1 (usually)    localhost  3.3
  Reports server + engines (ORB)    all interfaces         127.0.0.1  4.1
  rwservlet ORB in WLS_REPORTS      all interfaces         127.0.0.1  4.2
  Engine jvmOptions in rwserver.conf  no ORBServerHost     + 2 opts.  4.3
  AdminURL in startup.properties    host name / IP         localhost  5.1
  ADMIN_URL in $DOMAIN_HOME/bin/*.sh  host name            localhost  5.2
  EM emoms.properties (3 files)     host name              localhost  5.3
  Nginx 443 / 80                    all interfaces         stays      -
  (F) = Forms only

  Stays on the host IP by design (the firewall closes it, STEP 8):
  - Coherence cluster port 7574 (tcp / udp) and one more Coherence port -
    not removable with Oracle settings;
  - Reports multicast discovery (UDP, e.g. 14022) - the Reports server
    needs it for its start;
  - frmweb sockets (Forms only) - no Oracle option for a bind address,
    no host name inside.
  - The mail sender in rwserver.conf (reports@<host>) is host-specific on
    purpose - not an error (STEP 4.4).

  Not part of this run (only important when the server is cloned): own
  RCU prefix for an external repository, Nginx name and certificate,
  tnsnames.ora, own Reports broadcast port. Next step for that:
  ../FormsReports14_linux_clone/README.md

  4.3 Engines with their own jvmOptions (rwserver.conf)

  #   ... engLife="50" jvmOptions="-Xms1024m -Xmx2048m" defaultEnvId="QS"/>
  #   -> next command (sed).

KNOWN PROBLEMS
================================================================================

  Problem : EM shows WLS_REPORTS (or WLS_FORMS), its cluster and the
            reports deployment red / shut down, but status.sh says
            RUNNING. AdminServer.log shows only BEA-149505 "... JMX
            Service URL of <none>".
  Cause   : the Node Manager started the managed server directly with the
            old AdminURL from startup.properties (host name / IP). The
            AdminServer listens only on localhost, the managed server runs
            "in Managed Server independence mode".
  Solution: STEP 5.1, then restart the managed server through the Node
            Manager / autostart. Check the running process:

  ps -ef | grep '[w]eblogic.Name=WLS_REPORTS' | grep -o 'management.server=[^ ]*'

            Expected (test host): management.server=http://localhost:7001
            Still an IP / host name -> report the output.

  Problem : clone_check shows "tcp 0.0.0.0:<port> rwEng-0 all
            interfaces", the Reports server itself is on 127.0.0.1.
  Cause   : <engine ... jvmOptions="..."> in rwserver.conf replaces the
            inherited REPORTS_JVM_OPTIONS - ORBServerHost is missing for
            the engines.
  Solution: STEP 4.3, then restart the Reports server (complete restart
            STEP 6, or the Reports server alone through the EM / Node
            Manager). Check with 7.4.

  Problem : emoms.properties shows the host name again after the restart
            (7.5).
  Cause   : the template under servers/AdminServer/tmp/_WL_user/em/... was
            not changed, or the EM was extracted again (EM patch,
            redeploy, tmp/ emptied).
  Solution: STEP 0 (find EMTMP again) and STEP 5.3, restart the
            AdminServer. Check again after every EM patch.
            NO outage: the EM works with the host name there too.

  Problem : Reports server does not start, rwserver_diagnostic.log shows
            REP-50125 : java.lang.NullPointerException ... at
            oracle.reports.utility.Utility.getOrbProperties
  Cause   : REPORTS_JVM_OPTIONS is set, but without
            -DORBWaitForResponseTimeout=... - Oracle then reads the value as
            empty and aborts. The same after STEP 4.3 when the jvmOptions
            are broken (quotes).
  Solution: add -DORBWaitForResponseTimeout=999999999 to the line
            REPORTS_JVM_OPTIONS=... in reports.sh (STEP 4.1); check the

            engine line of STEP 4.3; then restart the Reports server.
            Otherwise ROLLBACK of the file.

  Problem : report hangs or REP-51002 / "Bind to server failed" after
            the restart.
  Cause   : only 4.1 or only 4.2 done - rwservlet and the Reports server
            do not find each other.
  Solution: grep ORBServerHost in reports.sh and setUserOverrides.sh
            (STEP 4), then STEP 6.

  Problem : scripts or a managed server do not reach the AdminServer
            ("Connection refused" on t3://<host>:7001).
  Cause   : called with the host name - 7001 listens only on localhost.
  Solution: use t3://localhost:7001 (STEP 5.2; also the ADMIN_URL of the
            oracle profile and patch_install.ini of the tools).

  Problem : an application no longer reaches http://<host>:9002/reports/...
            (or :9001/forms/...).
  Cause   : it went past Nginx so far (STEP 1.4).
  Solution: use https://<host>/reports/... In an emergency: ROLLBACK.

  Problem : WLS_REPORTS / WLS_FORMS log BEA-2194505 (warning about
            localhost) or "Local address 127.0.0.1 is a loopback address;
            this cluster node will not connect to nodes located on
            different machines".
  Cause   : intended - Coherence talks over 127.0.0.1 only.
  Solution: KNOWN AND HARMLESS.

  Problem : clone_check_fmw.sh does not report the places of STEP 4.3 /
            5.3 although they hold old values.
  Cause   : old version of the tool (before 2026-11-10.8).
  Solution: STEP 1.1.
