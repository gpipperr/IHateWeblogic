# wlsmon – operations and troubleshooting

← [11-wlsmon](../README.md) · concept: [01-wlsmon_concept.md](01-wlsmon_concept.md)

State 2026-11-20: one host with both roles (data + GUI) live on the test
host. Paths below use the default `WLSMON_BASE=$ORACLE_BASE/admin/wlsmon`.

---

## 0. Users and accounts

Before the installation: which accounts must already exist, which ones the
scripts create, and what each is for. Passwords are never typed on a command
line; the new ones end up as systemd credentials (`etc/creds/*.cred`) or as
hashes in `/etc/nginx/wlsmon/`.

| Account | Kind | Exists before / new | Created by | Used for | Secret |
|---|---|---|---|---|---|
| `oracle` (FMW owner) | OS user | **must exist** | the FMW installation | runs `00-` and `01-`; the collector service runs as this user (`User=` of the unit) | – |
| `root` or `oracle` with sudo | OS | **must exist** | – | runs `02-` (group, ACLs, credentials, Nginx, systemd) | – |
| `nginx` | OS user | **must exist** | the `nginx` package (`09-Install/04-root_nginx.sh`) | serves the GUI and the JSON files, reads them through the group `wlsmon` | – |
| `wlsmon` | OS **group** (system group) | **new** | `02-` (`groupadd -r`; members `nginx` and the FMW owner) | read access of Nginx to `www/`, `api/`, `hosts/` – `nginx` never joins `oinstall`. A running `oracle` login sees the new group only after a new login (setgid trap, section 4) | – |
| Domain administrator – the user stored with `00-Setup/weblogic_sec.sh` (`WL_USER` in `weblogic_sec.conf.des3`, any name, e.g. `webadmin`) | WebLogic user, group **Administrators** | **must exist** | the domain | **once** in `01-`: creates / checks the monitor user through REST; never at runtime. `01-` loads it from the library – log line `Credentials loaded for user: <name>`; without the library it asks `WebLogic admin user:` and the password (memory only) | not stored by wlsmon |
| `wlsmon_monitor` (`WLSMON_MON_USER`) | WebLogic user, group **Monitors** only | **new** | `01-` (REST `createUser` + `addMemberToGroup`) | read-only REST call of the collector every 5 min (state, heap, threads, JDBC) | generated by `00-` (password rule of the realm), credential `wls_monitor` – nobody needs to know it |
| `monUser` (`WLSMON_REPORTS_MON_USER`) | Reports user (role `RW_MONITOR`) | **must exist** | `09-Install/12-oracle_reports_users.sh` (library installs) or the customer | `getserverinfo` of the Reports servers (engines, queue, jobs) | from `reports_users.conf.des3` or asked by `00-`, credential `reports_mon` |
| GUI users (`WLSMON_GUI_USERS`) | Nginx Basic Auth only – no OS / WebLogic account | **new** | `00-` (asked, twice) → `02-` (htpasswd) | login of the people to `/wlsmon/` (GUI role) | hash in `/etc/nginx/wlsmon/htpasswd` |
| `wlsmon_pull` (`WLSMON_PULL_USER`) | Nginx Basic Auth only | **new** (P2) | `00-` on the GUI host (generated; the hash is entered on every data host) → `02-` | GUI host fetches the JSON of the data hosts | credential `pull_user` on A, hash in `/etc/nginx/wlsmon/pull_htpasswd` on B, C, D |
| DB monitor user (`WLSMON_DB_MON_USER`) | database user | **must exist – optional** | the DBA (agreed per customer) | hourly RCU schema check (`WLSMON_RCU_CHECK=true`, off by default): `SELECT` on `DBA_USERS` for the RCU schemas only | asked by `00-`, credential `db_monitor` |

Short form: on a library host only `oracle`, `nginx`, the domain administrator of `weblogic_sec.sh` and
`monUser` must be there; wlsmon adds the OS group `wlsmon`, the WebLogic user
`wlsmon_monitor` and the GUI logins – nothing else changes in the domain.
Removal: `02- --remove` deletes the group and the htpasswd files; the
WebLogic user `wlsmon_monitor` is only listed by `01- --remove` (the domain
stays untouched).

## 1. Install and remove

```bash
# 1. FMW owner: questions -> etc/wlsmon.conf + etc/pending/ (dry-run shows the diff)
./11-wlsmon/00-setup-interview.sh
./11-wlsmon/00-setup-interview.sh --apply

# 2. FMW owner: program, GUI, ui.json, WebLogic monitor user, collect --check
./11-wlsmon/01-install-wlsmon_fmw.sh
./11-wlsmon/01-install-wlsmon_fmw.sh --apply

# 3. root (or the FMW owner with sudo): group, ACLs, credentials, nginx, systemd, first run
sudo ./11-wlsmon/02-install-wlsmon_root.sh
sudo ./11-wlsmon/02-install-wlsmon_root.sh --apply
```

Every script shows what it would do without `--apply`. Options:
[concept §9.2](01-wlsmon_concept.md#92-installation-scripts).

| Task | Command |
|---|---|
| Change a setting | `00-setup-interview.sh --apply` (offers the current values), then `02-install-wlsmon_root.sh --apply` for web-tier keys (section 3) |
| Change one secret | `00-setup-interview.sh --secret NAME --apply`, then `02-install-wlsmon_root.sh --apply` (encrypts it) |
| Monitor user lost its password | `01-install-wlsmon_fmw.sh --reset-monitor-password --apply` |
| **Remove** | `sudo 02-install-wlsmon_root.sh --remove --apply`, then `01-install-wlsmon_fmw.sh --remove --apply` – `etc/` stays and is listed, the WebLogic monitor user is listed for manual removal |

Updates (new wlsmon version, Oracle patch cycle, APEX patch): section 1a.

## 1a. Update

No reinstall – what to do depends on what changed. `etc/` (configuration,
local rules, credentials), `state/` (time series) and the JSON files are
never touched, so the history simply goes on.

**New wlsmon version** (repository or tools ZIP):

```bash
git pull
./11-wlsmon/01-install-wlsmon_fmw.sh --apply        # copies only changed files ("installed" vs "unchanged")
sudo ./11-wlsmon/02-install-wlsmon_root.sh          # dry run: did an nginx / systemd template change?
sudo ./11-wlsmon/02-install-wlsmon_root.sh --apply  # only when the dry run shows a change
```

`01-` copies `bin/wlsmon.py`, `share/wlsmon_rules.cfg` and `www/`; the next
timer run already uses the new program. Then reload the page with
**Ctrl+F5** – the browser keeps the old JS and CSS otherwise.

**New Oracle patch cycle (CPU / CSPU) applied:** nothing to copy – the
collector reads the patch level once a day from the inventory files. Raise
the **expected** cycle, otherwise the patch tab reports the new level as
off-baseline (or keeps reporting the old one as current):

```bash
./11-wlsmon/00-setup-interview.sh --apply   # "Expected patch cycle YYYY-MM", e.g. 2026-12
```

or set `WLSMON_PATCH_BASELINE=2026-12` in `$WLSMON_BASE/etc/wlsmon.conf` –
read at the next run, no restart. For the library this is a step of the cycle
switch ([update_lib_to_act_cpu.md](../../docs/update_lib_to_act_cpu.md), J).

**APEX patched** (new JET / font-apex version below `/i/`):
`01-install-wlsmon_fmw.sh --apply` rewrites `www/ui.json` with the newest
library paths, then Ctrl+F5. Hosts without APEX use the own SVG charts and
icons – nothing to do.

**Changed setting, secret or monitor password:** table in section 1.

## 2. Is it running?

```bash
systemctl list-timers 'wlsmon*' --no-pager          # next / last run (every 5 min)
systemctl status wlsmon-collect.service --no-pager  # result of the last run
journalctl -u wlsmon-collect.service --since -1h    # output and errors of the runs
```

Expected output: one run every 5 minutes, `status=0/SUCCESS`, a few
hundred ms each.

| What | Where |
|---|---|
| Result of the last round | `$WLSMON_BASE/api/now.json` (`generated_at`, `level`, `collector.errors`) |
| Overview tile (single host) | `$WLSMON_BASE/hosts/hosts.json`, `hosts/<id>` is a symlink to `../api` |
| Time series, offsets, pauses | `$WLSMON_BASE/state/` (`series.json`, `state.json`, locks) |
| Collector errors | `now.json` → `collector.errors`, shown in the GUI; the journal for crashes |
| Check by hand (FMW owner) | `python3 $WLSMON_BASE/bin/wlsmon.py collect --check` – one round, printed, nothing written; WebLogic REST and Reports are skipped without the credentials of the service |
| Resources | the journal line "Consumed … CPU time" per run, `systemd-cgtop` during a run – limits `CPUQuota=10%`, `MemoryMax=200M` |

The GUI shows **stale** when `generated_at` is older than two intervals –
the collector watches itself that way.

## 3. Configuration

`$WLSMON_BASE/etc/wlsmon.conf` – `KEY=value`, read by `wlsmon.py` at each
run; reference of all keys: [concept §9.3](01-wlsmon_concept.md#93-configuration-reference-wlsmonconf).

- Collector keys (thresholds, ports, servers, disks): take effect at the
  next run – no restart.
- Web-tier keys (`WLSMON_ADMIN_IP_RANGE`, `WLSMON_GUI_USERS`, `WLSMON_GUI_IP`,
  `WLSMON_STYLE_SRC`) and the core directory: only through
  `02-install-wlsmon_root.sh --apply` (renders the nginx include and the unit).
- Local log rules: `$WLSMON_BASE/etc/wlsmon_rules.local.cfg` (never
  overwritten); test a rule against a log copy with
  `wlsmon.py rules --test LOGFILE`.

Secrets are not in `wlsmon.conf`: systemd credentials in `etc/creds/*.cred`
(root, host bound), the htpasswd files in `/etc/nginx/wlsmon/`
([concept §3b](01-wlsmon_concept.md#3b-password-storage--systemd-credentials-no-library)).

## 3a. Change the WARN / CRIT levels afterwards

The levels are keys in `wlsmon.conf` – no reinstall, no restart: the next
timer run (at most 5 minutes) uses the new values, and the limits printed
under the key-figure tiles change with them.

**With `03-set-thresholds.sh`** (FMW owner, as often as needed – the usual
way in the first weeks):

```bash
./11-wlsmon/03-set-thresholds.sh                                  # overview, changes nothing
./11-wlsmon/03-set-thresholds.sh --set HEAP_PCT=85,95             # dry run: old -> new, checked
./11-wlsmon/03-set-thresholds.sh --set HEAP_PCT=85,95 --set FORMS_SESSIONS=150,180 --apply
./11-wlsmon/03-set-thresholds.sh --interactive --apply            # ask each key: Enter = keep, - = default
./11-wlsmon/03-set-thresholds.sh --reset HEAP_PCT --apply         # back to the built-in default
```

- The **overview** puts every threshold next to the value measured now and
  the maximum / average of the last 24 h (`day.json`); a limit the last 24 h
  reached is marked WARN – the first hint that it fires in normal operation.
- Values are **checked before anything is written:** two numbers, WARN
  below CRIT (reversed for the certificate days), percent 0..100. A bad value
  stops the run, nothing is written.
- `--apply` keeps a backup `wlsmon.conf.bak_<timestamp>`, changes only the
  named lines (adds a key that is not in the file yet) and runs
  `collect --check`. Keys may be given with or without `WLSMON_`.
- Needs the current program: after a `git pull` run `01-install-wlsmon_fmw.sh
  --apply` first (the script warns when `bin/wlsmon.py` is older).

**Other ways:** the interview (`00-setup-interview.sh --apply`, answer "y" at
"Change the thresholds") or an edit of `etc/wlsmon.conf` by hand (copy it
first, check with `python3 $WLSMON_BASE/bin/wlsmon.py collect --check`).

**Format `warn,crit`:** two numbers, a value **at or above** the first is
WARN, at or above the second CRIT. A value the collector cannot read (e.g.
`85;95` after a hand edit) falls back to the built-in default and is
reported in `collector.errors` – shown in the GUI.

| Key | Default | Measured value | Note |
|---|---|---|---|
| `WLSMON_HEAP_PCT` | `80,90` | heap used % of each WebLogic server | |
| `WLSMON_CPU_PCT` | `80,95` | CPU % since the last run | |
| `WLSMON_LOAD` | cores, 2 × cores | load average 1 min | not asked by the interview – add the line by hand, e.g. `WLSMON_LOAD=6,12` |
| `WLSMON_MEM_USED_PCT` | `85,95` | memory **used** % = 100 − `MemAvailable` % | the tile shows *free* %; its level is the worse of this and the swap limit |
| `WLSMON_SWAP_MB` | `512,2048` | swap in use, MB | shown under the memory tile; until 2026-11-20 any swap meant WARN |
| `WLSMON_DISK_PCT` | `80,90` | fullest of the watched file systems | which ones: `WLSMON_DISKS` |
| `WLSMON_LOG_ERRORS` | `1,10` | counted log errors per run and component | which messages count: log rules below |
| `WLSMON_FORMS_SESSIONS` | empty = no limit | active Forms sessions | set per environment, e.g. near `maxRuntimeProcesses` |
| `WLSMON_REPORTS_QUEUE` | `5,20` | queued Reports jobs | |
| `WLSMON_CERT_DAYS` | `30,7` | days until a certificate expires | **reversed:** lower is worse – WARN at 30 days or less, CRIT at 7 or less |
| `WLSMON_RCU_DAYS` | `30` | days until an RCU schema password expires | one number (WARN below it) |

Stuck threads (> 0 = CRIT), hogging threads (> 0 = WARN), a DOWN component
and core dumps have fixed levels – they are always worth a look.

**Levels of log messages** come from the rules, not from `wlsmon.conf`. In
`$WLSMON_BASE/etc/wlsmon_rules.local.cfg` (never overwritten by an update) a
rule with the **same id** replaces the default rule of
`share/wlsmon_rules.cfg`:

```
# lower a default rule from crit to warn
match;db_closed;warn;*;ORA-17008|ORA-03113;DB restart window every night (agreed 2026-11-20)
# drop a known harmless message - a reason is mandatory
ignore;forms_noise_01;-;forms;FRM-93652.*WebUtil;checked in the Forms logs 2026-11-20, client closed by the user
```

Test a rule against a copy of a real log before it goes live:
`python3 $WLSMON_BASE/bin/wlsmon.py rules --test <logfile> --source wls,forms`.
A rule with a bad regex is skipped and reported in `collector.errors`.

## 4. Known faults and their fix

| Symptom | Cause | Fix |
|---|---|---|
| **403** on JS / CSS / JSON, host page without data, overview **stale** | files below `www/`, `api/`, `hosts/` are not group `wlsmon` – the setgid bit of the directories is gone. Linux clears setgid on every `chmod` by an owner who is not in the file's group; an oracle login older than the `usermod -aG wlsmon` of `02-` is such an owner (2026-11-20) | `sudo 02-install-wlsmon_root.sh --apply` (group, 2750, 640). `01-install` changes modes only when they differ and warns when a file is not group `wlsmon` |
| `hosts.json` 404 on a single host | collector older than 2026-11-20 (wrote no own tile) | `01-install-wlsmon_fmw.sh --apply` |
| Disk WARN for the core directory, but the disk is fine | `PrivateTmp=yes` hides `/var/tmp/core` from the service | unit with `BindReadOnlyPaths=-<core dir>` – `02-install-wlsmon_root.sh --apply` |
| Host WARN "Memory free" | used memory at or above `WLSMON_MEM_USED_PCT`, **or** swap in use at or above `WLSMON_SWAP_MB` (free memory may look fine while the host already swaps) | look at the swap figure under the tile; change the limits with `03-set-thresholds.sh` (section 3a) |
| nginx error count contains the monitor's own probe | older collector counted the security probe of `/management/weblogic/latest` from 127.0.0.1 | `01-install-wlsmon_fmw.sh --apply` |
| REST components "n/a", 401 in `collector.errors` | monitor user password differs from the credential; the collector pauses 30 min after a 401 (`WLSMON_401_PAUSE_MIN`, avoids the realm lockout) | `01-install-wlsmon_fmw.sh --reset-monitor-password --apply` |
| `rep_<server>` "not checked" in `collect --check` | the check by hand has no service credentials | normal – the service reads `reports_mon` |
| Service does not start, `LoadCredentialEncrypted` error | a `.cred` file named in the unit is missing | `02-install-wlsmon_root.sh --apply` – it keeps only the credential blocks whose file exists |
| Charts drawn as plain SVG, no JET | `/i/libraries/oraclejet/<ver>` not found (APEX upgrade changed the version) | `01-install-wlsmon_fmw.sh --apply` rewrites `ui.json` with the newest versions |
| No tooltip on the large charts | JET `hoverBehavior: 'dim'` suppresses the data-cursor tooltip (JET 20.1.4) | fixed in `wlsmon_charts.js` 2026-11-20 – update + Ctrl+F5 |

**Debug the GUI without the login (test host only):** back up
`/etc/nginx/oracle-wls.d/wlsmon.conf`, comment the two `auth_basic` lines,
`nginx -t`, reload. Afterwards restore the backup (or
`02-install-wlsmon_root.sh --apply`, which renders the file again) and check
that `/wlsmon/host.html` answers 401.

## 5. Access checks (curl, on the host)

```bash
SN=$(hostname -f); R="--resolve $SN:443:127.0.0.1"
curl -sk $R -o /dev/null -w '%{http_code}\n' https://$SN/wlsmon/host.html          # 401 (login)
curl -sk $R -o /dev/null -w '%{http_code}\n' -X POST https://$SN/wlsmon/api/now.json  # 401/403 (POST refused)
```

With a login: 200 for the GUI and the seven JSON files, 404 for every other
file below `/wlsmon/api/` and `/wlsmon/hosts/`, 403 from an IP outside
`WLSMON_ADMIN_IP_RANGE` ([concept §6](01-wlsmon_concept.md#6-nginx)).
`02-install-wlsmon_root.sh --apply` runs the local part of these checks at
its end.
