HOW TO READ THIS COOKBOOK
--------------------------------------------------------------------------------

  - All commands in a "cmd" shell started with "Run as administrator".
    Only where it says so, in PowerShell ("--- type in PowerShell ---").

  - Every command stands alone, with an empty line before and after it.
    Directly below: "REM Expected:" = what is right.

  - Lines ending with "^" and a "for ... do ( ... )" block are ONE
    command - copy them completely.

  - The variables are in ONE file builder_env.cmd (STEP 0). In EVERY new
    cmd shell first:   call E:\oracle\builder_env.cmd

  - Input INSIDE a tool (WLST, PowerShell) stands between
        REM --- type in WLST ---
        REM --- end of WLST ---
    and is indented further.

  - Expected output is shown for an ENGLISH Windows; where a German
    Windows answers differently, both are given.

PREREQUISITES  (adapt the values ONCE to the environment - STEP 0)
--------------------------------------------------------------------------------
  All commands in a "cmd" shell started with "Run as administrator"
  (Oracle: otherwise the configuration fails silently). The installation is
  done with ONE local administrator account (e.g. ORASYSTEM) - always the
  same one.

  DEVELOPER USER ACCOUNTS  [live 2026-10-27]
  ------------------------------------------
  With a normal user account (without admin rights) the Builder does NOT
  start after the installation:
  - The Oracle installer breaks the inheritance of permissions below
    E:\oracle during the installation (sets own, explicit permissions on
    the subfolders).
  - A group that is given rights on E:\oracle (e.g. "Reports developers",
    read/execute) therefore does not arrive in the subfolders.
  - The rights would have to be set folder by folder by hand - a lot of
    work, error-prone and to be checked again after every patch
    (assumption: OPatch creates files with the rights of the installation
    account).
  Decision: the developers work via RDP with an account with LOCAL
  ADMINISTRATOR RIGHTS on this server.
  - One OWN account per developer (personal, do not share ORASYSTEM),
    member of the local group "Administrators".
  - The server is only used for Builder development (no production, no
    other services); access only via RDP from the admin / developer
    network.
  - Licence side effect: Windows Server allows 2 simultaneous admin RDP
    sessions WITHOUT RDS licences - fits 2 developers; from the third
    simultaneous user on, clarify RDS licensing with the customer.

  Rules:
  - Paths WITHOUT blanks and short (Windows: long environment variables
    break Reports - Oracle Install 12.2.1.3 appendix B.3).
  - Do NOT change the host name and IP after the installation.
  - Prefer an English Windows (error messages for Oracle Support).
  - Anti-virus: exclusion for E:\oracle during installation and patching
    (patch READMEs: "anti-virus software should be temporarily stopped").

STEP 0: Set the variables  (cmd as administrator, in EVERY new shell)
================================================================================

  ----------------------------------------------------------------------------
  0.1 Create the variable file  (ONCE)
  ----------------------------------------------------------------------------
  mkdir E:\oracle

  notepad E:\oracle\builder_env.cmd

  REM Paste this content, adapt the values to the environment, save.
  REM No blanks at the end of a line (cmd takes them into the value).

  REM --- content of E:\oracle\builder_env.cmd ---

      set ORACLE_BASE=E:\oracle
      set ORACLE_HOME=E:\oracle\fmw
      set JAVA_BASE=E:\Java
      set JDK_HOME=E:\Java\jdk-21
      set JAVA_HOME=%JDK_HOME%
      set PATCH_STORAGE=E:\oracle\patch_storage
      set DOMAIN_HOME=E:\oracle\user_projects\domains\rwbuilder_domain
      set STAGE=E:\oracle\stage
      set LOGDIR=E:\oracle\stage\logs
      rem RCU database (existing database of the customer) and own prefix:
      set DB_HOST=<db-host>
      set DB_PORT=1521
      set DB_SERVICE=<pdb-service>
      set DB_SCHEMA_PREFIX=RWDEV

  REM --- end of builder_env.cmd ---

  ----------------------------------------------------------------------------
  0.2 Load  (in EVERY new cmd shell)
  ----------------------------------------------------------------------------
  call E:\oracle\builder_env.cmd

  ----------------------------------------------------------------------------
  0.3 Check
  ----------------------------------------------------------------------------
  echo OB=%ORACLE_BASE% OH=%ORACLE_HOME% JDK=%JDK_HOME% DH=%DOMAIN_HOME%
  REM Expected: all four filled. Shows "%...%" -> repeat 0.2.

  echo PS=%PATCH_STORAGE% STAGE=%STAGE% LOGDIR=%LOGDIR%

  echo DB=%DB_HOST%:%DB_PORT%/%DB_SERVICE% prefix=%DB_SCHEMA_PREFIX%
  REM Expected: real values, no <...> placeholders any more.

  if "%DB_HOST%"=="" echo EMPTY - DB_HOST missing, check 0.1

  ----------------------------------------------------------------------------

  REM the alert build - the 21.0.13 of the CPU itself is affected)

  cd /d %PATCH_STORAGE%

  tar -tf p35702194_2100_MSWIN-x86-64.zip | findstr /i "jdk-21"
  REM Expected e.g.: jdk-21.0.13.0.2_windows-x64_bin.zip

  tar -xf p35702194_2100_MSWIN-x86-64.zip -C %STAGE%

  REM Put the name from the output above WITHOUT "_windows-x64_bin.zip" here:

  set JDKVER=jdk-21.0.13.0.2

  echo %JDKVER%> %LOGDIR%\01_jdkver.txt

  dir %STAGE%\%JDKVER%_windows-x64_bin.zip
  REM Expected: the file is there. "File Not Found" -> JDKVER wrong

  tar -xf %STAGE%\%JDKVER%_windows-x64_bin.zip -C %JAVA_BASE%

  dir %JAVA_BASE%\%JDKVER%\bin\java.exe
  REM Expected: java.exe exists

  ----------------------------------------------------------------------------
  1.3 Version-neutral path as a directory junction
  ----------------------------------------------------------------------------
  REM A later JDK update is then only: new JDK next to it, close the
  REM Builder, set the junction again (rmdir %JDK_HOME%, then mklink).
  REM NEVER "Remove-Item -Recurse" on the junction (PowerShell 5.1 deletes
  REM the content of the target otherwise).

  mklink /J %JDK_HOME% %JAVA_BASE%\%JDKVER%
  REM Expected (English Windows):
  REM   Junction created for E:\Java\jdk-21 <<===>> E:\Java\jdk-21.0.13.0.2
  REM German Windows:
  REM   Verbindung erstellt fuer E:\Java\jdk-21 <<===>> E:\Java\jdk-21.0.13.0.2
  REM Check independent of the language: dir E:\Java shows jdk-21 as
  REM <JUNCTION> with the target in square brackets.

  %JDK_HOME%\bin\java -version
  REM Expected: java version "21.0.13..." and Java(TM) SE Runtime Environment
  REM (NOT "OpenJDK")

  ----------------------------------------------------------------------------
  1.4 JAVA_HOME system-wide
  ----------------------------------------------------------------------------
  setx /M JAVA_HOME %JDK_HOME%
  REM Expected: SUCCESS: Specified value was saved.
  REM (German Windows: ERFOLGREICH: Der angegebene Wert wurde gespeichert.)
  REM Then open a NEW cmd shell as administrator and do STEP 0.2.

  ----------------------------------------------------------------------------
  1.5 SecureRandom fix
  ----------------------------------------------------------------------------
  REM Faster WebLogic start; not critical on Windows, but the same as on
  REM the Linux server. In the file
  REM   %JDK_HOME%\conf\security\java.security
  REM set the line like this:
  REM   securerandom.source=file:/dev/./urandom

  copy %JDK_HOME%\conf\security\java.security %JDK_HOME%\conf\security\java.security.orig

  notepad %JDK_HOME%\conf\security\java.security

  findstr /b "securerandom.source" %JDK_HOME%\conf\security\java.security
  REM Expected: securerandom.source=file:/dev/./urandom

  ----------------------------------------------------------------------------
  1.6 Database reachable?  (from the Windows server)
  ----------------------------------------------------------------------------
  powershell -Command "Test-NetConnection %DB_HOST% -Port %DB_PORT%"
  REM Expected: TcpTestSucceeded : True

STEP 10: Operation, patching
================================================================================

  Patching: in every patch cycle the same numbers as on the Linux server,
  in the Windows variant (step 4). Close all Builder sessions first. JDK
  update: new JDK into E:\Java, set the junction E:\Java\jdk-21 again
  (step 1.3).

  The AdminServer does NOT have to run day to day. It is only needed to
  create a further tools instance or to change the domain.

  RCU database day to day  [measured 2026-10-27, check the Builder GUI at the customer]
  - The Reports tools do NOT use the RCU schemas at runtime: measured
    with strace on the Linux test system (rwconverter, same runtime and
    same tools instance as the Builder) - no OPSS / wallet file opened, no
    connection to the AdminServer, the only DB connection is the login of
    the report itself.
  - The RCU database is only needed to: change the domain, create a
    further tools instance, start the AdminServer - and for a later
    version upgrade (the Upgrade Assistant updates schemas AND domain;
    without schemas = new installation). OPatch patches do not need it.
  - Own RCU DB on this server: keep schemas and DB, but set the DB service
    to start type "Manual" - saves RAM for the RDP sessions. Start it only
    for domain changes / upgrades:

  sc config OracleService<SID> start= demand

  net stop OracleService<SID>

  REM when needed again:  net start OracleService<SID>

  - Check once (the Builder GUI is not measured yet): stop the DB service,
    start rwbuilder.bat, connect to the application DB, create a preview.
    If that works, it is confirmed.
  - Set the profile RCU_USER (no password expiry) for RWDEV_* anyway - an
    expired account is otherwise only noticed when the AdminServer is
    needed.

KNOWN PROBLEMS
================================================================================

  Problem : The Builder does not start with a normal user account, even
            when a group has read/execute rights on E:\oracle
  Cause   : the Oracle installer breaks the inheritance of permissions
            below E:\oracle (explicit rights per subfolder) - the group does
            not arrive further down  [live 2026-10-27]
  Solution: developer accounts as local administrators (prerequisites,
            "User accounts"); setting the rights by hand per folder is not
            recommended (a lot of work, again after patches)

  Problem : "MSVCP100.dll was not found" when the Builder starts
  Solution: install the Visual C++ Redistributable x64 AND x86 (step 1)

  Problem : The AdminServer does not start (for a domain change / upgrade),
            errors about OPSS / database
  Cause   : RCU DB service not started, password of an RWDEV_* schema
            expired or account locked
  Solution: start the DB service; DB team: profile RCU_USER, unlock the
            account (step 5)

  Problem : The preview in the Builder looks different from the PDF of the
            server
  Cause   : other fonts / uifont.ali than on the Linux server
  Solution: step 8.3, Font_kochbuch_de.txt

  Problem : Reports errors because of too long paths / environment variables
  Cause   : Windows limit for environment variables (Oracle Install
            12.2.1.3 appendix B.3)
  Solution: short paths without blanks, do not make PATH longer than needed

  Problem : The report runs in the Builder, but not on the server
  Cause   : different patch level Builder / server, other connection
            aliases, images / libraries not in the REPORTS_PATH of the
            server
  Solution: compare lspatches of both sides; align tnsnames and paths

  Problem : Unpacking a patch reports "path too long"
  Cause   : 256-character limit (per the patch READMEs)
  Solution: unpack with %JDK_HOME%\bin\jar -xvf (step 4.3)
